# Office 选区 AI 编辑技术方案

状态：核心链路已实现，按下表范围开放；macOS ARM64 已通过 CSV 在两个宿主的真实模型对话、指定单元格修改及原路径保存。Word、PPT 完整桌面会话和其他平台实机验收仍有待完成项。适用文件：DOCX、XLSX、CSV、PPTX；适用宿主：聊天右侧文件 tab，以及由该聊天打开的独立文件浏览器。

## 目标与实现边界

用户在原生编辑页面选中内容，点击 Word/表格的“AI 编辑”或 PPTX 的“Slides · Request edits / 请求修改”，输入要求后选择“添加”或“发送”。输入栏按稳定指令组保存选区与要求，发送后 Agent 使用本轮固定引用修改实际模型，由宿主核对内容并保存原文件。没有选区标签的普通文档任务保留当前文档规则。

实现复用本地 `office-docs-ai-engine`、Electron、React、Lexical、Zustand 和已有 Agent 通道。页面使用项目维护的本地浮层，SDK 内置在线 AI 保持关闭。不依赖外部应用，不提供 Agent 新建文档；分享与上传保留 TODO。

| 部分 | 当前状态 |
| --- | --- |
| 固定引用 | Server 生成引用身份；实际 pageId 与 engineFileId 共同确定模型代次。页面同步冻结原选择，提交输入后核对真实模型；不在 IPC 往返后重读光标替代目标 |
| 页面与宿主 | 三格式共用沙盒 preload、发送者校验及本地浮层；两宿主共用 OfficePanel。没有聊天归属的系统打开文件不显示可执行入口 |
| 输入栏 | Lexical 可编辑指令段落、原子选区标签、悬浮卡片、键盘移除；主动删除最后一个标签保留要求为普通文字，不显示重选操作；系统失效的要求仍需重选或明确改为普通文本 |
| 文件切换 | 文件面板和文件浏览器提交目标前检查；原生系统模态框位于编辑视图上方。Office 目标先隐藏准备，失败或取消不清理原草稿；已接收和排队快照独立保留 |
| 消息与执行 | 普通 prompt、queue、steer 接收时绑定真实用户消息；复用 assistant parentID 的归属。选区轮次的工具发现、修改及保存必须提供本轮 selectionRef，不能回退当前文件 |
| 历史与重启 | 产物清单持久化展示及模式标记，不保存可执行坐标和内容证明；重启后旧选区任务要求重选，不降级执行普通当前文件任务 |
| 共同基线 | 同轮同文档按正文、子表或页面共享基线；不改变坐标的多个引用可连续写入，坐标改变后要求重新选择；未知写入结果暂停，不重放 |
| 保存交付 | 手动保存规则保留；Agent 保存及后台交付均先核对本轮确认基线，再保存对应原文件 |
| 标签定位 | 核对仍有效的草稿引用后，在已显示编辑页定位 Word 范围、当前子表的单块/完整维度、当前 PPT 页的普通文本框。隐藏文件、其他子表/页、PPT 文字子范围的自动跳转暂不支持，明确提示手动打开或重选 |

### 格式与资源范围

普通 Word 空段落的起止坐标相等时，SDK 省略的文字字段规范化为空串；非空节点缺字段和截断正文仍拒绝采集。PPT 全选末段文字设置样式时，允许段尾回车同步继承本次属性；局部选字不得连带修改未选文字或段尾。

Word 页内单段或跨段选择若以结构回车 `\r` 结尾且原文长度与 GCP 范围一致，选区读取边界将结束坐标减一，文字预览同步去掉最后一个结构标记。中间分隔符、空段和正文空白全部保留；换行或长度不一致的占位符不套用此规则。只选择一个段落结束符时不显示文字 AI 入口。

- Word：支持单段和跨段连续普通正文的替换、加粗、斜体、颜色和字号，包含首尾只选一部分及中间空段。每个正文节点必须能完整读取，最多 256 个节点、每节点最多 200 个 UTF-16 码元，涉及段落的字符属性读取合计最多 256 个码元，同时读取段落属性。跨段改写保留段数，输入按原段顺序以 LF、CRLF 或 CR 分隔，空段也占一项；每段改写后的完整正文不得超过 200 码元，涉及段落的正文合计不得超过 256 码元。段数不匹配或预算不足时在任何写入前拒绝。当前不支持通过选区合并、拆分或删除段落，复杂结构和超长段落仍拒绝采集。页面入口需要非空文字选择，光标插入仅保留契约。
- 表格：真实 sheetId 与选中矩形内写值、公式、样式及读取。完整行列采用 SDK 原生维度标记，不从有限矩形推断。普通核对覆盖已用数据与选区边界，最多 4096 格；合并区拓扑必须不变，选区不能切开合并单元格，内容只能写合并区左上角。无关标题合并区不阻断正文编辑。
- 空白单元格样式：SDK 会把目标空白格物化为空字符串单元格；只接受选区内这一确定性附带效果。有公式或多个工作表的工作簿暂不开放此操作，避免改变计数等公式的语义。普通已有单元格样式不受此限制。
- 行列删除：单工作表、无公式、无合并单元格时开放，完整网格不超过 8192 格；回读全部单元格、格式和网格变化，坐标改变后旧引用失效。复杂工作簿不执行扩大范围的替代操作。
- PPT：普通文本框整框改写，或框内 UTF-16 文字范围的加粗、斜体、颜色和字号。整页、组内对象、图表、备注及局部保真文字替换暂不开放；不得以整框替换冒充局部文字替换。每页最多 128 个形状，目标文本框最多 4096 码元。
- 单次内容证明最多 4 MiB；每聊天最多 64 个未发送登记，一次消息最多 16 个引用、32 个指令组。常驻执行基线总预算 64 MiB；关闭、恢复或失效时释放该模型的证明，旧轮次标记仍保留。

## 用户交互

### 编辑页浮层

1. 用户完成选区并点击“AI 编辑”。宿主先在原选区仍可确认时完成采集，再让输入浮层取得焦点。浮层默认宽 280 px、高约 36 px，窄窗口内自适应；仅显示“说说你想怎么修改”输入框及圆形确认按钮，没有尾部关闭图标或下拉箭头，输入多行时按内容增高。
2. 确认按钮默认执行“添加”；悬停确认按钮时显示“添加 / 发送”及快捷键，移出按钮和菜单区域后隐藏。键盘聚焦确认按钮时同样可访问选项。Enter 添加；macOS Cmd+Enter、Windows Ctrl+Enter 发送；Shift+Enter 换行；Escape 取消。输入法组合期间任何提交键均不执行。
3. 添加把选区及要求放入原有草稿，不替换草稿文字、附件或其他选区。没有要求时允许仅添加选区；只有标签而没有实际指令时不直接启动修改。
4. 发送与聊天发送使用同一提交和队列入口：已有草稿一并发送，不静默丢弃其他内容；任务运行中按现有规则排队，不启动另一条绕过队列的 Agent 任务。
5. 添加或发送成功后关闭浮层。发送失败、未被接收或排队失败时保留草稿、标签和修改要求，并显示实际失败原因；不能因为点击了按钮就清空。
6. 没有可解析选区、文档只读、加载中、外部接管或页面恢复中，不开放可执行入口；不将光标或未知对象冒充文字选区。折叠光标只支持明确的插入操作。
7. 点击浮层外部立即收起输入浮层，未添加的内容不写入聊天草稿，并释放候选引用；该次点击继续交给原编辑页处理。采集仍在等待时也可取消，迟到回复不得重新打开浮层。已发起添加或发送的操作交由宿主完成，不因关闭外观在接收途中撤销引用。
8. 入口同时监听鼠标、键盘及原生文字选区变化，并在下一绘制帧读取最终范围。PPT 选中文本框边框或拖选框内文字后显示入口；仅放置文字光标不建立文字选区。
9. 未关联聊天的独立文件也保留选区入口，点击时提示先将文件添加到目标聊天再打开，不自动绑定最近聊天。已知采集失败使用本地中文原因，不展示 IPC 通道或通用运行时异常。

PPTX 页内入口采用 Presentation SVG、Slides 品牌和 amber 视觉，文案固定为“Slides · Request edits / 请求修改”；只有 `kind === "slide"` 使用该呈现，Word 和表格继续显示原有通用“AI 编辑”入口。三种格式的同一动作都提供 `data-jugglework-office-action="request-edits"` 稳定选择器，自动验证和宿主集成不得依赖本地化文案或脆弱 CSS。

Slides 入口只改变产品呈现，不改变安全与交付边界：点击后仍同步读取并核对候选选区，完成原有 capture 握手后冻结 `selectionRef`；添加、发送和取消沿用同一桥，Server 仍按文档代次、内容证明和范围约束执行并回读验证，随后才允许保存和交付。页面不直接调用 `slide_*` 工具，也不因 Slides 品牌入口重读当前视觉选区、扩大写入范围或绕过保存证明。

浮层由项目代码在 SDK 页面内部绘制，避免原生 WebContentsView 覆盖宿主 React 浮层。原生选区、页面提交和本地 Agent 分别使用已适配的接口；浮层的指针、焦点、提交键与组合事件先于 SDK 全局事件处理。不得通过按钮中文、脆弱 CSS 选择器或 SDK 压缩模块编号识别动作。

### 输入栏与历史消息

每次明确“添加”生成一枚不可部分编辑的行内标签，可与普通文字、附件及同文件的其他选区标签混排；标签之后是该次修改要求。三种标签样式分别用于三类文件；首版每个聊天的未发送草稿只绑定一个选区文件，普通切文件使用下述确认规则。相同采集请求重复回调去重，用户重新添加同一范围属于新的明确操作。仅移动编辑页光标或改变选区，不新增、替换或移除草稿标签。

指令组采用 Lexical 段落节点保存 instructionId，只有选区标签是不可部分编辑的原子节点。要求文字使用普通 TextNode，换行、范围选择、上下移动及撤销重做与主输入栏共用同一套逻辑，不嵌套独立输入框；普通键入不重建文字节点或重置光标。Shift+Enter 换行及多行粘贴后的内容仍属于原指令组。

Backspace/Delete 紧邻标签时一次移除整枚标签，其他位置逐字删除，范围删除只删除所选内容。左右方向键跳过标签内部按钮。移除行首标签时，若存在上一段则将光标放在上一段末尾；首段没有上一段时留在当前段起点，修改要求保留。输入法组合期间不触发标签删除。

复制或剪切导出可读标签与完整要求，不显示内部草稿 token。撤销恢复要求文字；已释放引用不会因撤销自动恢复执行权限，需明确重新选择。主动删除最后一枚标签仍按普通文字规则处理，不显示重选提示。

标签内容与悬浮卡片：

| 格式 | 标签 | 卡片第二行 |
| --- | --- | --- |
| DOCX | 文档选区 | 选中文字摘要；没有文本时显示明确的光标位置 |
| XLSX、CSV | 表格选区 | 子表名称及 A1 范围，如 `sheet1!A8`、`明细!A1:B2` |
| PPTX | 幻灯片选区 | 页码及形状数量；文字子选区额外显示文字摘要 |

输入栏标签高 22 px、字号 12 px、左右内边距 6 px、图文间距 4 px；默认显示对应的选区类型图标，悬停或键盘聚焦时同一个左侧图标位替换为删除按钮，不额外占用右侧空间。未填写修改要求时，标签后保留空白输入位置。

悬停卡片优先在标签上方左对齐，宽 282 px、内边距 12 px、圆角 16 px；窄窗口内自适应，使用现有 Tooltip Portal 避开输入栏滚动裁剪，并由定位组件处理屏幕边界。第一行使用现有文件类型图标及文件名，第二行显示上表中的选区信息；表格不额外展开单元格内容。键盘聚焦同样可查看卡片和移除标签。长文件名和长摘要截断显示，卡片提供的文字不能代替结构化坐标。

点击标签定位其文档与范围，使用已有文件 tab；不能因此新建第二个编辑模型。范围失效时保留卡片历史信息并提示“选区已变化，请重新选择”，不定位或修改另一个相似内容。聊天历史显示相同标签和卡片，但历史标签没有执行权限；复制为纯文本不产生有效引用。

### 确认切换文件

此确认保护未发送的聊天选区草稿，与文档是否已经保存无关。首版采用“草稿选区绑定当前文件”的交互：切换到另一文件前确认，确认后清除草稿选区标签。跨文件保留标签并在同一草稿合并执行不属于首版交互；后续若开放须显式调整切换规则，不能让两套策略同时生效。

触发条件：本聊天当前草稿存在任意选区引用，且即将激活的目标与其中任意引用不是同一文档，或者关闭所引用文档使目标变为其他文档或空态。无效、过期的标签也参与检查，不能因为无法执行就静默移除。检查发生在目标改变之前，不能先改 tab 再监听 activePath 补弹窗。

| 操作 | 确认行为 |
| --- | --- |
| 当前没有未发送的选区标签 | 直接切换 |
| 点击另一文件 tab、产物卡片、正文文件链接、附件预览或文件列表 | 激活另一文件前确认；Office 与非 Office 文件遵循相同规则 |
| 文件选择器、最近打开、Cmd/Ctrl+O、拖入打开、系统打开请求 | 用户实际选定目标后检查；取消文件选择器不弹窗 |
| 同一聊天的独立窗口打开/选择另一文件，或在另一窗口添加另一文件的选区 | 使用同一聊天草稿检查，不能绕过侧栏规则 |
| 关闭所引用文档，随后激活相邻文件或进入空态 | 确认关闭并清理草稿选区；文档保存决策仍单独执行 |
| 关闭无引用的后台 tab | 不弹此选区确认，仍执行该文件原有保存流程 |
| 同一文档从右侧迁移到独立窗口、再次定位同文件、切全屏 | 不弹、不清理，仍遵循原有迁移能力限制 |
| 切换聊天 | 各聊天保留自己的草稿，不清理；待确认请求随所属聊天切换取消 |
| 收起右侧栏、切到后台、最小化、普通失焦 | 不改变文件身份，不弹、不清理 |
| 已经接收或排队的消息 | 不受本次草稿清理影响，仍按自己的固定选区执行 |

切换弹窗使用截图中的标题“确认切换文件”，正文“对话框有文档选区。如果切换查看新文件，当前选区将被清空。是否确认切换？”，提供“取消”和“确认”。关闭、Escape 等未明确确认的动作等同取消，默认焦点落在取消；关闭文件时标题和正文明确描述关闭。两宿主复用共享宿主的原生系统模态框，不卸载编辑模型，不依赖网页 z-index。

确认仅移除本次展示给用户的未发送选区标签及对应的草稿引用登记，保留普通提示文字、修改要求、附件、文件引用和其他输入内容。与被移除标签绑定的修改要求改为“待重新选择”，保持其原有指令归属，不能降级成针对新文件的普通指令。不能调用 `clearSession` 或把整个 draft 设为空。若移除后没有标签，仍保留文字草稿；存在待重新选择的指令时阻止发送，提供重新绑定选区或明确改为普通文本的操作，不自动发送。取消则标签、草稿、活动文件及文件模型均保持原状。弹窗打开期间新增或改变选区标签时重新核对，旧确认不能批准删除后来添加的标签。

目标文件不存在、权限不足、引擎不适配、页面建立失败，或后续保存/关闭被取消时，不清理草稿。切换准备阶段完成文件身份、可用性、页面加载及已有生命周期检查，保留原模型；成功后再提交活动目标与已确认标签的移除。准备阶段创建但最终未激活的页面遵循现有资源清理规则。仅切 tab 不强制保存旧文件；实际关闭或外部接管时才遵循对应保存流程。

### 统一切换入口与跨窗口协调

增加应用级 `requestFileTargetChange` 协调入口，参数包含 workspaceId、sessionId、目标文档身份、操作种类和来源窗口。所有会改变文件目标的入口先调用该入口；底层 Zustand store 只提交状态，不在 store 中弹窗。使用已有宿主文档身份比较同一文件，尚未打开时通过现有文件身份解析处理符号链接、大小写和平台路径，不能只比较文件名或自己把所有路径转小写。

挂接位置：右侧 `files-panel.tsx` 的选择、`files-panel-store.ts` 的 open/select/close 调用方、正文与产物/附件的统一打开操作、`file-window-app.tsx` 的 action，以及 Electron `file-windows.mjs` 的打开、选择和关闭请求。原生编辑页的打开快捷键和系统打开文件同样汇入宿主协调入口；后台模型更新、自动保存和单纯文件扫描不触发用户切换确认。

聊天草稿仍由主渲染器的应用级草稿服务持有，独立窗口通过 Electron 向该服务请求检查，不复制一份选区草稿。该服务挂在应用根部，不能依赖当前聊天页面是否挂载。弹窗显示在发起操作的窗口；所属聊天或窗口已销毁、桥断开、请求超时均取消切换，不默认视为确认。每个请求明确绑定所属 scope 与目标，窗口内一次只呈现一个待确认目标，避免晚到的确认切换了另一个文件；不新增全局锁或持久化事务系统。

显示自定义弹窗时，暂时卸下遮挡它的原生 Office 视图并保留页面和模型，禁止用 CSS z-index 与 WebContentsView 争层级。弹窗结束后仅按当前仍有效的宿主布局恢复视图和焦点，避免已隐藏或已经切换的旧页面残留。

草稿清理只移除草稿所有权。本轮已接收消息持有自己的不可变选区快照，取消草稿关联不能删除该快照，也不能取消正在执行的任务。晚到的旧采集回调按原 captureId 去重，不能把刚清理的标签重新插回；新的明确添加仍可建立新引用。

切换流程为：解析目标 → 读取所属聊天草稿 → 必要时确认 → 预检并准备目标/生命周期 → 再核对本次确认的标签 → 提交目标和清理标签。取消或失败结束本次请求，保留原草稿；不需要为此重新设计文件模型或保存服务。

### 两种窗口与聊天归属

右侧和独立文件窗口共用一套桥、选区解析及提交规则。聊天打开的独立窗口始终向原所属聊天投递；即使当前主窗口显示另一聊天，也不能写入该聊天的草稿。所属聊天未显示时由草稿状态保存，明确添加成功后可定位该聊天。

从系统“打开方式”进入、尚未关联聊天的本机文件不自动选择最近聊天。第一阶段提示先将文件添加到目标聊天，再使用选区 AI 编辑；后续可提供显式关联会话入口，但不能创建第二份活跃模型或自动扩大文件访问范围。

## 三格式选区与修改边界

### Word

选区保存 SDK 返回的连续范围 `begin/end/length`，区间为 `[begin,end)`，保留所选文本和必要上下文。坐标来自 SDK，不按显示字符数、行号或段落序号重新计算。当前页内读取器从 `pad.editor` 取得连续范围；跨单元格等非连续内容不转换为外包字符范围。

修改前读取原文并核对范围。文本替换使用已验证 schema 的 `doc_replace_text`，传入确切 ranges 和新文本，不在整篇文档按显示文字全局替换；格式操作只使用已验证覆盖范围的字符格式工具。文档表格使用 tableId、行列语义，暂不纳入第一阶段连续文字选区。

跨段范围按结构树确认端点属于正文，相邻段必须满足后一段 `start_index = 前一段 end_index + 1`。`office.selection.contents` 返回固定范围内完整的 `paragraphs` 数组，包含空串；模型不能根据截断 preview 补全文字。选区工具目录声明宿主适配后的跨段契约，普通无引用工具保持原生契约。字符样式将范围分解为段内正文范围，不写段落分隔符。

原生 `doc_replace_text` 不接受段落分隔符。宿主先核对全部新段落及预算，再从后向前替换各段的所选文字，空段填字使用原位插入；不重建段落。写后按实际调用次数核对 revision，逐段核对文字、坐标、原有段落属性与未选字符格式，并核对全文长度。全部确认后才推进共同基线并允许保存，改变坐标后要求重新选择。中途出错或响应不确定时暂停整个选区任务，保留已发生的修改供用户核对，不回放写入，也不宣称保存成功。

第一阶段正文连续文字使用 SDK DOC 坐标，即包含结构分隔符的 UTF-16 坐标体系，不能把普通字符串长度直接当作全文位置。范围需确认属于可编辑的正文文本；跨表格、图片、字段等结构边界，页眉页脚、脚注或其他未适配子文档范围不能归入普通正文。`doc_resolve_document_structure` 的默认结果和 text_preview 都可能截断，不能作为完整原文。`doc_find` 没有范围过滤参数，出现相同文字时必须匹配已固定 begin/end，不能取第一个搜索结果。

### Excel、CSV

选区保存真实 `sheetId` 和零起始的行列范围，末端为闭区间。子表名称与 A1 字符串只用于展示；改名后仍使用相同子表身份。多块选择保留各自范围，不用最小包围矩形覆盖中间未选单元格。

写值使用 `sheet_set_cell_value`，样式使用 `sheet_set_cell_style`，每个写入单元格必须位于所选范围。删除行列使用 `sheet_delete_dimension`；整行或整列删除要求对应的行列选择语义，不把单个单元格选区自动扩展为整行删除。普通聊天明确指定“删除 CSV 第一行”的现有能力不受影响。

合并单元格必须查询实际合并区域；选区只覆盖部分合并区时要求用户选择完整范围。CSV 保持单表及 CSV 保存语义，不承诺保留颜色、字体或多工作表。含透视内容的只读工作簿仍不允许 AI 修改。

### PPT

分别表达整页、多个形状和单个普通文本框内部文字三类选区。保存真实页身份或可验证的页顺序、`pageIndex`、`shapeIds`；文字子选区另有 `shapeId/start/count`。文字偏移按 UTF-16 码元计数，跨段落计入分隔符，反向选择先规范化。

整框文字修改使用 `slide_set_text`，只作用于所选形状；选中文字格式使用 `slide_set_text_property` 的 index/count。一个形状 ID 不能代表框内的选中文字。页顺序变化或形状已删除后，不能仅沿用旧 pageIndex。

当前配套 SDK 没有已验证的、保留其他字符样式的局部文字替换工具：对框内几个字的改写，不能自动退化为整框重写。第一阶段支持文字范围格式修改、明确整框文本替换；框内局部文字改写须完成保真适配后另行开放。备注、母版、组内对象、SmartArt、框选区域及 PPT 表格选区不作为第一阶段支持项。

### 强类型定位与操作范围

`selection.kind` 必须细化为以下判别类型，不能只保留 doc/sheet/slide 和一段显示文字：

| 类型 | 必需定位字段 | 第一阶段允许的内容动作 |
| --- | --- | --- |
| `doc-text` | 非空 ranges，原生 begin/end，正文范围证明 | 在范围内替换文字、设置已适配字符属性 |
| `doc-caret` | 原生 idx，正文范围证明 | 在该光标插入文字；不冒充已选文字 |
| `sheet-cells` | 真实 sheetId、各个闭区间行列矩形 | 范围内写值、公式、已适配单元格样式 |
| `sheet-rows` | 真实 sheetId、完整行选择语义、行区间 | 对应完整行的已适配动作，包括删除所选行 |
| `sheet-columns` | 真实 sheetId、完整列选择语义、列区间 | 对应完整列的已适配动作，包括删除所选列 |
| `slide-pages` | 页身份或 pageIndex 与页顺序摘要 | 查询选中页并把已适配编辑解析到该页的真实形状；不默认开放所有页面工具 |
| `slide-shapes` | 已验证页定位、非空 shapeIds | 对所选普通文本形状进行明确整框替换或已适配样式操作 |
| `slide-text` | 已验证页定位、唯一 shapeId、start/count | 在范围内修改文字样式；局部保真文字替换待适配 |

表格原生读取器当前只返回网格范围，尚未保留完整行/列选择意图。必须在页面适配中确认该语义；无法确认时只能建立 `sheet-cells`，不能由 A1 文案或矩形末端恰好覆盖网格来猜测。合并区、整页 PPT、形状类型及页顺序也必须在采集或执行解析时由模型证明。

宿主负责从引用生成坐标参数，Agent 负责新内容与修改要求。Agent 可以指定引用内更小的明确范围，宿主校验包含关系；传入的 file_id、sheet_id、page_index、shape_id 等若与引用冲突则拒绝，不静默改投目标。范围不能通过选中文字再次全局搜索获得。

| 操作 | 已核对的工具与参数映射 | 写前、写后核对 |
| --- | --- | --- |
| Word 文字替换 | 选区通道宿主适配 `doc_replace_text`；跨段 text 按原段数分隔，由宿主拆为倒序段内替换/空段插入 | 写前完整预检；写后核对各段文字、坐标、段落属性和未选字符格式；部分失败暂停且不重试 |
| Word 字符属性 | `doc_update_text_property`，ranges 取固定范围 | 只发送明确修改的属性，回读相关属性；保持范围外文字及属性 |
| Word 光标插入 | `doc_insert_text`，idx 取固定光标 | 回读原生位置及插入内容，不按肉眼字符数更新后续全文坐标 |
| 表格值或公式 | `sheet_set_cell_value`，sheet_id 和 row/col 限于引用 | 用 `sheet_get_cell_data` 回读相同 sheetId 与坐标；公式文本和计算值分别核对 |
| 表格样式 | `sheet_set_cell_style`，闭区间起止行列限于引用 | 仅修改明确属性，核对目标属性与未选择单元格 |
| 删除完整行列 | `sheet_delete_dimension`，dimension_type、index/count 来自行列引用 | 核对真实维度变化及相邻数据；旧坐标引用失效 |
| PPT 整框文字 | `slide_set_text`，page_index、shape_id 来自形状引用 | `slide_get_text` 回读同一形状，其他形状和页保留；不使用多目标参数扩大范围 |
| PPT 文字属性 | `slide_set_text_property`，index=start、count=count | 回读同一形状的相关文字属性，前后字符不被一起修改；不允许 count=-1 扩大为文本末尾 |

允许工具目录只包含完成“定位、范围校验、结果读取”适配的工具。查询 schema 不代表工具已经允许用于选区修改。多个不相邻矩形必须逐块校验，不能按包围矩形写入；PPT 批量参数中的每个形状和每个字符范围同样逐项校验。

## 架构与所有权

```mermaid
flowchart LR
    Page[浮层聚焦前固定 SDK 原生选区] --> Bridge[Electron 页面桥]
    Bridge --> Capture[Server 固定选区引用]
    Capture --> Draft[所属聊天草稿与 Lexical 标签]
    Draft --> Admit[原有消息提交与队列]
    Admit --> Turn[绑定 messageId 的本轮选区列表]
    Turn --> Agent[原有 Agent 与按需工具发现]
    Agent --> Guard[选区目标与写入范围校验]
    Guard --> Model[已打开的同一 SDK 模型]
    Model --> Verify[回读目标内容与修改结果]
    Verify --> Save[页面提交确认与宿主保存]
    Save --> Delivery[本轮文件交付与卡片]
```

Server 的 `OfficeDocuments` 是文档模型及引用的唯一所有者。Electron 根据 IPC 发送者绑定的实际 webContents、workspaceId、documentId 和页面代次确定目标。页面传来的 fileId、文件名、路径、聊天 ID 仅能作为观测数据，不决定执行目标。窗口迁移保留同一模型身份时引用可保留；关闭重开、外部接管、崩溃恢复和引擎重启后旧引用不可执行。

只对“打开浮层、添加、发送”等明确动作采集或固定引用；不建立选区全局轮询，不为每次鼠标移动生成服务端记录。底层的选区变化事件只更新页内候选选区，不能等同于用户添加。页面桥仅开放配套选区动作，沿用既有隔离与网络允许规则，不向页面开放任意 IPC、脚本执行、文件访问或在线业务代理。

客户端分别登记草稿、队列和发送中请求持有的引用。普通发送、steer 和队列预检在第一次异步等待前固定本次引用，直到消息接收流程结束或队列快照接管；这期间删除标签或清空输入栏不能释放该请求的引用。请求成功、取消或失败后结束临时持有，仅释放其他草稿、队列和请求均不再使用的引用。服务端已接收轮次持有独立快照，不依赖输入栏继续显示标签。

### 采集时序与焦点

采集以一次 captureId 表示，分为“准备、冻结、添加/发送”三个步骤：

1. 在 AI 入口将要取得焦点时，保留原生选择对象与所属页面身份。若仍处于输入法组合，等待用户完成组合，不提前提交拼音。
2. 在原选区仍可确认、浮层尚未聚焦时，通过已有页面提交适配确认编辑缓冲已进入实际模型，再采集原生范围、该范围完整内容、必要结构及内容基线。若提交改变了原选择而无法证明对应关系，取消本次采集并提示重新选择，不能读取折叠光标代替。
3. 范围与内容基线必须属于同一模型状态：使用已验证的原生一致读取能力，或比较读取前后的可靠版本/确定性模型状态。状态不一致不建立引用，不把一次旧范围和另一次新内容拼成快照。
4. Server 生成 capture 对应的不可变候选快照后，浮层才接受输入焦点。用户移动光标或进入其他输入框不替换此快照。尚未点击添加时不进入聊天草稿，取消浮层释放候选。
5. 添加/发送仅引用已冻结快照，核对模型、页面及内容适用性。不能在此时调用现有实时 `readSelection` 重新选择目标；延迟回调不延长快照有效性。

原生回调如果仅在“添加”时才提供坐标，必须另有已验证的入口前采集或原生冻结证明。缺少这项能力时使用项目页内浮层先完成上述握手；不得因为原生浮层外观相同就认为原选区已固定。同步冻结值由已绑定的原生页面提供；Server 持有实际模型身份，核对冻结文字与原生内容。后来的光标变化不替换这个值。

### 固定引用契约

新增强类型 `OfficeSelectionReference`，替代新增功能继续扩展通用 `Record<string,unknown>`：

| 字段 | 来源及用途 |
| --- | --- |
| referenceId | Server 生成；标签、指令及本轮列表按此关联，不使用时间戳作唯一身份 |
| workspaceId、ownerSessionId、documentId | 已有宿主文档归属 |
| modelGeneration | Server 模型代次；不能由页面指定 |
| kind、selection | 上述八种强类型定位；保留格式与原生坐标语义 |
| contentStamp | 可证明坐标适用的内容版本或语义摘要 |
| captureId、sourcePageId | 去重及采集证明，不能替代文档模型身份或内容版本 |
| contentProof | 完整目标内容/属性的确定性摘要与必要结构，不使用截断预览作证明 |
| capturedAt | 展示与诊断时间，不代表引用仍有效 |
| preview | 文件名、子表名、范围说明及截断摘要；不参与写入定位 |

原生事件中的 opaque rangeId、selectionId 和页版本可以作为适配输入，不能替代 Server 引用或默认视作可靠的文档修订号。选区文本属于文档数据；修改要求单独存储为用户指令。

### 内容变化与失效

实现前必须验证 SDK 是否提供覆盖用户输入、撤销、重做及 Agent 写入的可靠内容版本。验证通过才可采用该版本。

没有可靠版本时，采用 Server 从实际模型读取的确定性语义快照摘要：Word 包含结构与文本，表格包含目标工作表的网格结构、值、公式及操作涉及的格式，PPT 包含页顺序、对象身份和目标页内容。仅比较选中文字、文件 mtime、dirty 标志或磁盘哈希不足以判断未保存模型的坐标是否仍适用。摘要在本地计算，不把完整内容重复注入模型。

语义快照必须声明覆盖域及完整性；相关属性进入当前动作的证明，不能只取节点摘要、前 200 字或未翻完的查询页。未获得完整所需数据时不生成“有效”的 contentStamp。模型级读取按绑定模型和明确范围进行，不要求其页面成为当前活动 tab；隐藏页面不得因此回退到当前可见文件。未能提供无副作用的范围/属性读取的格式或动作暂不开放。

第一阶段保守处理变化：从采集到执行若适用范围的版本或摘要变化，就拒绝旧引用，不做文字搜索重定位，也不引入 OT、CRDT 或坐标变换算法。文档内容未改变时，光标变化、聊天切换和同模型窗口迁移不使引用失效。无法在资源预算内完成确定性核对时提示缩小范围或重新选择，不跳过核对。

同一文档的多个引用不能在一次范围变更后继续盲用旧坐标。第一阶段一个草稿可包含同文档多个选区，换文件前按确认规则清理；同一文档涉及可能改变坐标的多个修改须由宿主先形成完整操作计划、按安全顺序执行，未实现该计划时提交前要求拆分执行。字符替换、行列删除与重叠范围不能仅靠 Agent 自行排序宣称安全。

## 输入栏、消息与 Agent

### 草稿表示

复用现有字符串草稿与结构化 parts 模式：草稿字符串中的内部 token 只保存 referenceId；Zustand 保存对应引用预览，Lexical 新增原子标签节点，序列化保持同一 ID。标签的实际坐标不写入可编辑字符串。

选区及其修改要求组成有稳定 instructionId 的结构化指令组：`referenceIds` 明确列出关联选区，`text` 是用户可编辑要求，`bindingState` 为 bound、needs-selection 或 detached。Lexical 导出的有序 parts 保留组身份与关联，不能靠发送时解析“标签后面的那句话”恢复绑定；字符串草稿只承担展示与已有输入兼容，不决定执行权限。

浮层自动插入的要求直接进入对应组；用户在组内修改文字仍保留绑定。多个选区有不同要求时分别成组，要求同时作用于多个选区时显式关联这些引用。用户点击删除或使用标签删除键，移除最后一个引用时，保留要求文字并将组设为 detached，不显示“请重新选择要修改的内容 / 重新绑定 / 改为普通文本”；发送不再携带该选区的执行引用，后续添加的新选区另建指令组，不接管旧文字。仅删除多个引用中的一个时，其余引用仍保持绑定。

切文件确认、文档关闭或模型失效等系统清理，使相关组变为 needs-selection，保留要求并阻止发送；输入栏提供重选及改为普通文本操作。重新选择后须明确重新绑定该组；修改几个文字或粘贴文本不自动解除待绑定状态。草稿中的主动删除不影响已接收或排队消息持有的引用。

`ComposerPart` 增加 `office-selection`；普通文本、附件、队列项、失败恢复和历史渲染都保留此 part。粘贴伪造 token、纯文本历史或只有 ID 而没有宿主记录时不能获得有效引用。

发送前预检所有引用；任一已经失效时保留整个草稿，不发送一个悄悄缺少标签的请求。服务器接受消息后以 workspaceId、sessionId、实际 messageId 绑定本轮引用列表，排队的消息在真正执行前再次核对。提交重试使用现有 admissionId 去重；只有消息已被接收后才清空草稿，结果未知时先查询接收状态，不能自动重复发送。

Server 同样拒绝 needs-selection 的指令组，不能只靠按钮禁用。消息提交携带引用 ID、指令组及有序可见文本；Server 根据自己持有的记录构造本轮快照。内部 token 和显示标签不能直接拼成引擎请求中的可执行坐标。请求入口的严格 schema、前端 prompt 转换、队列/steer admission 与插件都需同步此契约；主机侧字段在转发给引擎前被消费，不假设上游接受自定义参数。

引用预览和历史元数据可随消息持久化；可执行身份仅存在于活跃文档与本轮上下文中。应用重启后历史标签仍可显示，但必须重新采集后才能执行。未发送草稿沿用现有内存生命周期，不新增明文凭据或独立持久化数据库。

### 查询与执行接口

以下是拟增加的契约，不代表当前已有接口：

| 接口 | 规则 |
| --- | --- |
| 页面 selection capture IPC | 在浮层聚焦前完成提交确认、冻结范围与同状态证明；添加/发送消费冻结结果 |
| `POST /workspace/:id/office/:documentId/selection-references` | Electron 绑定页面代次和 captureId，Server 校验冻结内容并返回 referenceId 与预览，不重读当前光标 |
| 现有消息提交增加 `officeSelectionRefs` 和 `officeInstructions` | Server 校验聊天归属、指令关联、就绪状态并构造本轮上下文；用户文本里的 ID 不视为提交字段 |
| `office.selection` 查询动作 | 只解析本轮显式引用，返回固定模型和格式选区；不读取当前 tab 替代它 |
| `office.tools` 的 selectionRef | 普通轮次保持原协议；选区轮次按有效引用发现工具，不回退当前活动文档 |
| `office.call` 的 selectionRef | 普通轮次保持原协议；选区轮次的写入强制带有效引用，缺失、失效或不属于本轮时拒绝，宿主派生坐标并校验范围 |
| `office.save_document` 的 selectionRef | 选区轮次保存已绑定的修改文档，不能因缺少引用或当前 tab 改变而保存其他文件 |
| `office.reveal_selection` 定位动作 | 只定位已验证引用或结果范围，不产生内容修改，不通过设置当前选区为后续写入授权 |

有显式选区引用的修改使用 selectionRef；旧的无标签当前文档编辑保留原语义，不将两种目标静默混合。工具需要 file_id 时由宿主绑定，不接受 Agent 替换模型身份。写入范围校验采用逐工具的明确映射，未知工具禁止用于选区写入，不通过字段名猜测写入范围。全篇替换、改变未选区域的工具和原生生命周期工具不能绕过选区通道。

### 本轮强制目标绑定

Server 在消息接收前建立不可由 Agent 修改的 `OfficeTurnContext`，包含 mode、真实用户消息身份、允许的 referenceIds、指令组以及模型代次。mode 只在接收时确定：有有效选区指令时为 selection，否则为 current-document；清理后仍有 needs-selection 指令的消息不能接收。

选区轮次所有 Office 写入和保存都必须进入固定目标通道，漏传 selectionRef 一律拒绝；即使本轮只有一个引用也不退回当前文件。只读查询也按明确目标区分，查询当前文件的结果不能成为本轮写入目标。`office.tools` 仅返回本轮引用支持的工具，普通内容通道不能绕过此限制。该约束在 Server 工具执行与保存入口执行，不依赖模型遵守提示词。

消息归属复用现有 admission 及交付轮次规则：前端关联 ID 经 `opencodeAdmissionId` 得到实际引擎用户消息 ID；工具调用的 assistant messageId 按真实消息 parentID 解析到用户轮次，不能将两类 messageId 直接相等比较。普通 prompt、队列、steer 与重复 admission 都使用同一映射，不能按“会话最近一条请求”查引用。归属未知或等待必要消息事件时不执行写入，也不读取上一轮选区。引用绑定在 admission 转发前准备，明确未接收则释放本次准备状态，接收状态未知则保留并按原 admission 查询/重试。

轮次解析由已有消息归属所有者统一提供，Office 消费已解析结果；需要复用的内部接口在原所有者处开放，不在插件和 Office 模块重复解释原始消息。Server 组合层注入该能力，保持 Office 内容服务与交付协调的原有依赖方向，不能新增二者的循环依赖。

本轮有显式引用时，Agent 上下文以本轮引用列表为选区来源，不再用 `office.current_document` 的实时光标覆盖它。无引用的当前文档查询仍可用于回答其他只读问题，但不能成为该选区写入的替代身份。

### 同文档执行基线与结果确认

执行状态以“实际用户轮次＋documentId＋modelGeneration”为键持有一个 `OfficeDocumentExecution`，共享覆盖域到内容基线的映射；referenceId 只保存各自范围和采集时证明，不各自维护一份会互相失效的执行版本。同文档同一子表的多个引用共用子表覆盖域，跨子表分别核对对应覆盖域并共享文档结构证明。

首次写入核对各引用的采集证明及文档状态。每次执行按以下顺序完成：

1. 按本轮与引用解析确切模型；核对代次、覆盖域基线、目标内容、坐标边界及工具范围映射。
2. 对选中内容生成明确工具参数，执行受支持动作；使用原生结果记录实际影响范围，不能把模型回复文本作为工具成功证明。
3. 从同一模型回读目标及必要邻接内容/属性，核对目标后置条件和未选区域。共同基线更新前，核对实际变化符合该动作已声明的写入范围及派生效果，不能把同时出现的其他修改直接吸收为成功。表格公式文本与用户输入值纳入定位证明，允许的公式重算结果单独校验，不把公式缓存变化当作用户越界写入。确认成功后，更新该文档执行状态中受影响覆盖域的共同基线；同轮其他不改变坐标的引用据此继续，不因第一格/第一个引用写入就误判失效。
4. 文字替换、插入或删除行列等改变坐标后，作废受影响的旧定位；只有原生返回且确认的新范围或宿主完整计划可继续写入。不得通过新文本长度手算全文位置，不能让其他引用仅因共同基线已更新就获得新坐标。
5. 写前拒绝不推进基线。明确无副作用的工具失败保留原状态；传输超时、回读失败或结果未知可能已发生修改，此时把执行状态标为待核对并暂停后续写入，不更新成功基线、不自动重试，不用后续成功掩盖未知结果。

表格公式回读比较允许前导等号和函数名大小写的表示差异，例如 `=sum(A1:A2)` 与 `=SUM(A1:A2)`。字符串常量、带引号的工作表名、结构化列名和单元格引用仍按原内容核对，不能整条公式转大写后比较；公式输入及 SDK 原始回读值保持不变。

上述执行状态复用既有串行内容调用，不新增全局锁。采集证明保持不可变；本轮受控写入不能自动刷新其他尚未发送或排队轮次的引用。用户修改导致实际状态与本轮预期不一致时停下并要求重新选择，不把未知变化吸收到新的成功基线。

每次动作返回宿主生成的编辑回执：本轮与文档身份、referenceId、已解析范围、原生调用结果、回读状态、结果定位（可为空）和保存状态。必须区分“已修改但未保存”“已保存”“部分完成”和“结果待核对”。保存仍调用原有页面提交与宿主原路径保存；只有回读确认及保存成功后才能报告完成交付，不能只凭 MCP 成功或 dirty=false 宣称修改正确。

### 可见定位与编辑定位

写入按固定坐标进行，不依赖界面焦点、滚动位置或视觉高亮。用户点击标签或结果的“定位”时，标签定位接口再校验模型与范围；若需要切换文档则先经过统一文件切换确认。首版仅在已经显示的所属编辑页恢复已适配的精确选择；不自动跨文件、子表或幻灯片页。各格式采用已验证的 SDK 定位适配，暂未具备时明确不可定位，不能用文字搜索跳到第一个匹配。

修改完成后原生页面沿用同模型更新，展示编辑回执摘要及可用的结果定位；如果用户已切到其他文档，不自动抢焦点或把原文件重新顶到前台。发生替换后旧选区可失效，结果定位必须来自经验证的原生返回值或回读结果，不继续高亮旧坐标。定位操作不能改变任何后续执行的目标授权。

Agent 获得精简的本轮引用列表、每条对应的修改要求以及按需查询入口。三种格式复用当前模型服务及内容工具，不新增第二套 AI；页面内的 AI 按钮不发往 SDK 自带在线 AI 服务。只有用户已配置的 Agent 模型服务按已有聊天链路接收执行所需内容。

首版每次显式选区消息绑定一个文档，可含该文档的多个选区；未发送草稿按切文件确认规则处理。消息已经接收后，即使用户确认切到另一文件并开始新草稿，原消息仍操作自己绑定的模型，不能改用最后打开的文件。成功修改按实际 documentId 记录到当前 messageId，保存成功后确认交付；部分失败报告实际结果，不自动回滚覆盖用户后续输入。后续多文档选区草稿不属于首版范围。

## SDK 适配与跨平台

当前配套 SDK 为 0.0.0.499。已通过实际本地引擎读取确认 Word 与 PPT 含 AI 能力判断，PPT 有选区添加/发送事件及页内选区收集链路；表格的完整 AI 入口和提交回调位于待核对的页面模块，不能用另一个格式的事件名称推定已适配。

已核对的配套集成代码把标签的选区坐标与显示摘要分开，发送上下文携带本轮结构化选区列表，选区标签与自动插入指令具有稳定的配对身份。这些静态事实支持本方案的引用、指令组和本轮列表设计；它们不证明浮层前冻结、原生修订号、服务端强制范围约束或所有平台已经通过实测。这几项均以本项目的实际 SDK 验收为开放条件。

接入以格式能力清单控制：入口、输入浮层、添加回调、发送回调、选区解析、内容适用性校验和实际工具范围均完成验证后才启用。只修改共享的宿主桥与版本适配，不改写 SDK 二进制、不增加联网依赖。PPT 内置在线 AI 配置保持关闭；项目自己的页内入口通过本地桥接入原有聊天，其他格式沿用相同规则。

| 平台 | 实施与验证 |
| --- | --- |
| macOS ARM64 | 首个真实验收平台；两宿主、中文输入、Cmd 快捷键、选区编辑、保存重开 |
| macOS Intel | 同一 JS 桥，使用本平台 SDK；验证编码、输入法、首次打开及独立窗口，不宣称迁移已通过 |
| Windows x64 | 同一 JS 桥与本平台 SDK；验证 Ctrl 快捷键、DPI、反斜杠路径、中文文件名及任务栏窗口 |
| 未供应原生 SDK 的平台 | 保留现有不可用状态，不显示可执行的选区 AI 入口 |

文件定位使用既有 documentId、真实路径与身份规则；不能为了发送选区自行拼接跨平台 file URL。跨窗口迁移仍遵循原有平台开放范围。新增业务不扩大 Office 页面公网访问权限。

## 实施拆分与验收

1. **契约与能力核对**：核对三格式入口前冻结、原生输入提交、添加/发送事件及可靠内容读取；完成八类选区、工具坐标映射与回读适配，确认无在线 AI 回退；未完成时保留受影响能力关闭状态。
2. **共享采集与草稿**：实现页面桥、Server 固定引用、两个宿主路由、Lexical 标签、悬浮卡片、删除、统一文件切换确认和草稿/队列恢复。此阶段不绕过现有消息提交。
3. **本轮执行**：补齐指令组与消息 admission 归属、强制选区模式、固定目标工具/保存、文档共享执行基线、编辑回读与回执；保持无标签编辑原有行为。
4. **实机交付**：三格式样本在两个宿主完成真实 Agent 修改与保存重开；分别完成三平台验证及安装包资源检查，再按能力开放。

必须覆盖的验收场景：

- 三格式均可打开输入浮层；添加保留已有草稿；输入法组合不误发；发送失败标签及要求均保留。
- 三种格式分别显示对应标签，悬浮卡片对应真实文件名与范围；同文件可添加多个标签，删除只移除当前标签。
- Word 选中文字后移动光标，仍修改固定原范围；取消切文件保留草稿，确认后只清选区标签；采集后在原范围之前插字，旧引用被拒绝。
- Excel 第二子表的 A1:B2 只修改该区域；子表改名、行列移动、删除及合并边界变化得到明确结果，未选数据和公式保留。
- PPT 的整框与框内文字分开处理；局部样式只改选中文字，局部文字保真改写未适配时不执行整框替换。
- 已发送的 Word 选区任务在用户切到表格后仍修改并保存原 Word；跨聊天不能使用引用，清理新草稿不能改变旧任务快照。
- 排队期间发生内容变化，在执行前拒绝旧引用；未变化时排队继续执行同一模型。
- 关闭重开、引擎重启、页面恢复后旧引用不可执行；同模型迁移、普通失焦不误用另一文件。
- 消息接收结果未知时不重复提交，历史复制和纯文本伪造 ID 不产生可执行选区。

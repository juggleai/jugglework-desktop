# 第一版实现与联调说明

日期：2026-11-06。两个仓库均在本地 `codex/desktop-meetings` 分支；尚未 commit、push、部署或对运行中的数据库执行迁移。

## 已落地

- Desktop 左侧会议入口、首页、会议号加入、预约／修改／取消、邀请同组织成员、RSVP、月历和日／周议程、按月历史记录。
- 群聊／单聊发起入口和会议卡片；当前组织群成员自主加入；普通在会成员可追加邀请。新增成员只进入会议聊天室，不加入或读取原单聊。
- 圆角图标与现有主题变量；会前本地预览、音视频开关、屏幕共享、成员列表、主持权转交、锁定、离开／全员结束。
- ZEGO Web SDK 直接接入；JuggleIM 原生聊天室复用现有连接；与旧通话仅共享设备占用保护，不调用 JuggleCall 会议接口。
- 主窗口持有媒体及 IM，入会时自动打开独立 Electron 会议窗口（音频与视频会议统一）；弹窗跟随会议窗口。关闭会议窗口先弹出确认：普通成员确认离开，主持人选择仅自己离开（自动转交主持权）或全员结束。成功停止媒体后才关闭窗口；请求失败则保留窗口显示错误。返回主窗口或最小化会议窗口时，主窗口显示带画面、麦克风／摄像头开关和离开按钮的小浮窗。异常窗口丢失时立即停止本地媒体。
- 应用运行时每 30 秒检查本人创建或已接受邀请的预约，提前 5 分钟显示应用内提醒。提醒按账号、组织、会议开始时间去重；应用退出后不保证提醒。
- 后端组织作用域 API、群成员实时校验、持久化会议与文件配置读取、服务端 Token04、JuggleIM 聊天室白名单、会议卡片发送。
- 全员结束先保存终态，再调用 ZEGO 禁止房间登录（覆盖旧 token 有效期）及 CloseRoom，销毁聊天室；失败工作保留在数据库，由每 30 秒的维护任务重试。
- 参会会话每 20 秒续期；90 秒无心跳视为离线，下一次入会续期按用户 ID 排序转交掉线主持人。全房间无心跳 90 秒后由维护任务结束。预约超过计划结束 30 分钟未举行则标记过期。

这些阈值是本版代码默认值，与前期草案候选阈值不同。不会按计划结束时间强制结束正在心跳的会议。

## 配置及启动顺序

1. Server 沿用现有迁移机制应用 `commons/dbcommons/sqls/2026110601.sql`，创建 `meetings`、`organization_meeting_settings`。两个表已加入租户资源清单。
2. Server 必须具备既有密钥加密配置和该组织可用的 JuggleIM 配置；会议路由与现有 IM 设置共用服务初始化条件。
3. 修改 Server 的 `conf/config.yml` → `meeting`：填写 AppID、32 字节 ServerSecret、人数上限；完成验证后启用。修改后重启 Server。
4. Desktop「会议 → 设置」只读展示配置状态。ZEGO 凭证不再写入数据库，不从旧配置表读取；同一 Server 下组织共享 ZEGO 项目，会议授权仍按组织隔离。
5. 未配置时仍可预约、浏览日历；实际入会会被前后端阻止。`admissionConfigured` 是部署验证确认，非自动探测。具体示例见 [文件配置说明](05-electron-verification-and-zego.md)。

用户稍后提供 AppID 即可继续配置；真实媒体联调还需要匹配的服务端 Secret。不要将 Secret 写进前端代码、原型或文档。

## 尚未验收／后续工作

以下不能因为代码通过构建就视为上线完成：

- 未使用真实 ZEGO／JuggleIM 账号完成双人媒体、聊天室白名单、全员结束、断网重连、25 人容量联调。
- macOS Electron 开发版已完成关窗确认和浮窗的实际运行验证，使用合成设备／测试服务响应，详见 [实测报告](05-electron-verification-and-zego.md)。打包后的 macOS／Windows、实际系统设备权限与屏幕选择仍未验收；屏幕音频暂未接入。
- 当前邀请通过持久化 IM 会议卡片实现；响铃／应答／取消只预留消息类型，尚未实现呼叫状态机，界面没有虚假的呼叫按钮。
- 应用退出后的服务端预约提醒、通知持久化投递重试未实现；卡片发送失败由界面提供重发。修改／取消后的旧卡片在打开时从 API 重取最新状态。
- 暂不包含主持人远程禁麦／移除成员、举手、设备选择器、虚拟背景、自动演讲者布局；「焦点布局」仅突出首个成员。大规模视频订阅优化待容量验证。
- 当前日历一次最多查询 93 天／500 场；没有跨组织、外部访客、周期预约、第三方日历同步、录制、字幕或 AI 纪要。

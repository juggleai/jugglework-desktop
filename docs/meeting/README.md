## 方案结论

在左侧「通讯／通讯录」下方增加「会议」，形成会议首页、预约、会议日历、会前预览和独立会议窗口。组织群内发起后，群成员可从群顶部横幅或会议卡片主动入会；单聊发起的会议从创建时就是支持多人的会议，可继续邀请同组织成员，不需要把原单聊转为群聊。

采用 **ZEGO Web JS SDK 承载媒体 + 现有 JuggleIM 连接承载消息互动 + 云端会议业务服务维护权威状态**。复用 IM 身份、组织、通讯录和消息机制，不另接 ZEGO ZIM。日历是会议数据的视图，首期不依赖 Google／Outlook。

首期完整闭环包含：即时会议、群自主入会、单聊邀请多人、单次预约、日／周／月会议日历、提醒、麦克风／摄像头、屏幕共享、会议内文字聊天、成员和主持管理、离会／结束、异常恢复。录制、AI 纪要、字幕、白板、外部访客和周期会议放到后续阶段。

## 已确认的技术边界

JuggleCall 用于音视频呼叫场景，不用于 Meeting。Meeting 直接通过 ZEGO Web JS SDK 管理媒体；会议中的呼叫、响铃、应答和取消使用 JuggleIM 自定义消息实现，不调用 JuggleCall 的呼叫接口或复用其会话状态机。与既有通话仅协调设备占用。

会内聊天已确认使用 **JuggleIM 聊天室**，复用现有 IM 连接。每场会议绑定独立 chatroomId，不创建隐藏群。图标使用圆润轮廓、圆角转折和圆头描边。

开发仓库及本地分支已确认：

| 仓库 | 本地分支 | 责任 |

| `/Applications/work/jugglework-desktop` | `codex/desktop-meetings` | UI、媒体、聊天室客户端、桌面窗口与权限 |
| `/Applications/work/jugglework-server` | `codex/desktop-meetings` | 会议 API、预约日历、ZEGO 配置与 token、聊天室生命周期 |

## 评审需要收敛的决策

以下是推荐默认值，尚未视为已确认的产品承诺；可直接在评审时调整。

1. 首期仅同组织已登录成员入会；群外同组织成员必须得到显式邀请。
2. 会议独立窗口；同账号同组织同时只有一个音视频会话，旧通话和会议互斥。
3. 群会议默认不呼叫全群；显式邀请才产生个人呼叫。普通参会者可邀请同组织成员，主持人可关闭此权限。
4. 预约提前 10 分钟允许进入，主持人进入后正式开始；日历默认 30 分钟，仅作计划，不到点强制结束。
5. 容量通过组织配置下发；首轮验证以 25 人房间、可见视频最多 9 路为候选目标，须以实测和套餐确认，不照搬截图数字。
6. 正常主持人离会前转交；意外断线保留 60 秒，超时服务端确定性移交；空房 5 分钟自动结束。具体阈值可配置。
7. 首期保留既有通话入口，新增「发起会议」；不承诺把进行中的旧 JuggleCall 通话无缝迁移为会议。

## HTML UI 原型 V1

打开 [独立 HTML 原型](prototype/preview.html) 即可评审，无需安装依赖。包含首页、日／周／月日历、预约表单、群聊／单聊会议入口、会前预览、会议宫格／演讲者布局、模拟共享、成员与聊天、邀请、离会／结束和明暗主题。

原型仅演示 UI，不调用真实设备、不连接 IM 或 ZEGO；示例日期固定为 2026-11-06，预约仅演示当天，数据刷新后重置。正式功能已开始实施，当前范围以实现说明为准。

ZEGO AppID 已在 `prototype/config.js` 的 `zego.appId` 预留为 `null`，由用户需要时提供。此文件仅为原型占位；正式接入采用组织能力配置下发公开 AppID，短期 token 由会议后端签发，服务端密钥不放入前端。

# 分期实施与验收

## 1. 实施边界

当前仅完成文档设计。以下任务全部为后续待办，未安装依赖、修改业务代码、创建后端接口或进行 SDK 实验。本轮不创建已实现的 OpenSpec 规范，不提交代码。

推荐按「技术验证 → 基础入会 → 群和多人互动 → 预约日历 → 稳定性及灰度」推进。中间阶段可内部试用，首期对外发布必须包含用户要求的群主动入会、单聊邀请多人和会议日历，不能只交付单聊视频按钮。

## 3. P0 必须验证的事项

| 问题 | 验证方式 | 未通过时处理 |
| --- | --- | --- |
| 现有 ZEGO 3.12.0 是否适用于 Electron 44 | 使用签名包做双人推拉、设备切换、摄像头与共享双流、续期和重连 | 固定升级候选；回归旧 JuggleCall，不直接覆盖全局 SDK |
| 服务端 token 和组织绑定 | 检查 room/user 权限、跨组织错误凭证、续期失效 | 先补后端鉴权；禁止客户端内置密钥代替 |
| 结束／踢出是否真的停止媒体访问 | 屏蔽被踢客户端的 IM 消息，验证其仍不能发流／收流或重新入房 | 接通供应商控制面或相应撤权能力；不把自觉退出当强制退出 |
| JuggleIM 聊天室是否能隔离 | 验证服务端建群、成员读写、历史权限、结束禁言、列表隐藏、消息计数 | 定向扇出方案另行评估；不能让 C 进入 A-B 原私聊 |
| Meeting 自定义呼叫消息 | 验证 ring/response/cancel、真实发送者校验、可靠服务端回调或 API 持久化后 IM 广播、多端首应答和过期处理 | 补齐状态持久化与回调；不改用 JuggleCall |
| 主窗口 IM 单例与会议窗口 IPC | 切换页面、主窗口最小化／关闭到托盘、渲染重载、重登 | 修正连接宿主生命周期，不能开第二个 IM 登录规避 |
| 媒体权限与屏幕来源 | macOS、Windows、Linux 实机；拒绝权限、撤销权限、显示器热插拔 | 形成平台能力矩阵；不支持项做真实降级，核心媒体失败阻断该平台发布 |
| 主持管理策略是否可兑现 | 全员静音、成员自行解除限制、共享竞争、主持转交并发 | 语义区分「请求静音」与「禁止发言」；不能承诺仅靠客户端命令实现强制策略 |
| 会议业务服务是否已有可复用能力 | 确认已确定仓库中的组织 API、持久任务、JuggleIM 服务端权限及 RTC 回调入口 | 明确后端新增范围和负责方，禁止只交前端假接口 |

## 4. 代码落点草案

所有新增名称为建议，不是本次新增的目录。

```text
apps/app/src/react-app/domains/meeting/
  types.ts / api.ts / store.ts             业务契约与状态
  meeting-page.tsx / meeting-calendar.tsx  工作台与日历
  meeting-detail.tsx / schedule-dialog.tsx
  prejoin.tsx / meeting-room.tsx           会前及会中
  participants-panel.tsx / meeting-chat.tsx
  meeting-card.tsx / meeting-invite.tsx    聊天和全局邀请入口
  runtime/zego-adapter.ts                  SDK 隔离
  runtime/im-adapter.ts                    复用 JuggleIM
  runtime/ring-controller.ts               自定义消息呼叫状态，不依赖 JuggleCall
  runtime/session-controller.ts           生命周期与恢复

apps/desktop/electron/
  meeting-window.mjs                      独立窗口
  meeting-ipc.mjs                         受限桥接
  media-session-coordinator.mjs           旧通话与会议互斥
  media-permissions.mjs                   扩展现有权限策略
```

同时修改 shell 导航及路由状态、主题与国际化、jugglechat 自定义消息注册／分发／卡片渲染、现有 call-store 的互斥接入、退出／组织切换流程和必要的共享类型。日历与云端会议服务使用相同模型，不接入本地自动化任务来代替组织级提醒。

后端建议按会议聚合、参与资格、RTC 凭证、IM 会话桥接、outbox、提醒投递和日历查询拆责任，已确认落在 `/Applications/work/jugglework-server` 的 `apis/`、`services/`、`storages/models/` 与 `routers/router.go`，配置遵循现有组织设置模式。

## 5. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 无 IM bootstrap／切换组织 | 会议入口不继承旧组织状态；旧组织会议不能跨上下文继续操作 |
| 工作台即时发起 | 创建单个会议并进入预览／会中；重复点击和网络重试不会生成多个房间 |
| 群 A 发起、B 未被单独邀请 | B 通过横幅／卡片自行加入；无需 A 逐个同意；非群成员无独立邀请则拒绝 |
| 同群两场并行会议 | 横幅可选择，卡片分别更新，不覆盖同一 RTC 房间 |
| A-B 单聊邀请 C | C 加入同一会议，能看到允许的会内历史，无法读到 A-B 私聊及原群历史 |
| 群成员退群／邀请撤销 | 新 join 和续期拒绝；在会资格重新计算并按策略移除，迟到 IM 事件不能恢复资格 |
| 邀请超时／拒绝呼叫 | 停止响铃，不结束会议；仍有资格者可主动加入；不误改 RSVP |
| Meeting 呼叫多端／乱序／重试 | 相同 ringId 不重复响铃；首个有效应答生效，其他设备停止；过期和取消后不被迟到消息重新唤醒 |
| Meeting 依赖边界 | 会议路径不调用 JuggleCall、getCallClient 或旧 call-store 的呼叫操作；呼叫走 JuggleIM 自定义消息，媒体走独立 ZEGO adapter |
| 收到未知版本／伪造会议消息 | 不崩溃、不执行管理动作；显示兼容提示或忽略非法通知 |
| 会议消息与普通聊天并行 | 普通会话顺序、未读、搜索不被控制事件污染；聊天室消息不泄露到普通列表 |
| 日历预约／改期／取消 | 三视图、详情、邀请卡片一致；旧提醒作废；终态不可入会 |
| RSVP 与实际参会 | 接受未加入不计入会人数；婉拒者仍可按有效资格重新响应／入会 |
| 时区／跨天／夏令时 | 同一 UTC 事件显示一致，无重复日程；无效本地时间明确提示 |
| 会前拒绝麦克风／摄像头权限 | 可选择降级入会；取消预览无残留设备指示灯 |
| 共享选择取消／源关闭／拔显示器 | 不发布错误源；共享停止，摄像头与音频按原状态继续 |
| 两人并发开始共享 | 服务端仅批准一个共享租约；失败方收到具体提示 |
| 旧通话与会议同时呼入／发起 | 只存在一个活跃媒体会话；不自动挂断当前会话 |
| 切换业务页面／主窗口最小化 | 会议持续，能从全局状态返回；IM 不重复连接 |
| 关闭会议窗口／退出应用 | 明确离会处理，tracks 和占用锁释放；关闭窗口不误结束全员 |
| 主持人转交／崩溃／重连 | 同一时刻一个主持人；断线宽限后移交，旧主持不抢回 |
| token 即将过期／资格已撤销 | 有效用户续期，无资格用户停止并提示；日志不含 token |
| IM 断开、RTC 正常 | 媒体持续，聊天可见不可用；业务快照补齐权限，不制造「会议已结束」误判 |
| RTC 断开、IM 正常 | 展示重连，按租约恢复；成员不被重复计数，不自动重新开麦 |
| 终态事件丢失／乱序／重复 | 快照最终收敛；旧事件不能复活会议；供应商撤权仍有效 |
| 容量并发争抢／第二设备登录 | 不超卖参会席位；租约抢占行为符合显式转移流程 |
| 发起成功但卡片发送失败 | 会议继续，outbox 重试；UI 提示分享通知延迟，重试不重复建会 |
| Desktop 离线／重启 | 不在本地伪造预约成功；恢复后拉取最新日程与未过期提醒 |
| 全员结束 | 所有在线端停止媒体，断线端不得重新加入；日历、横幅和卡片一致更新 |

测试层次：业务状态机／权限／版本幂等做单元与服务集成测试；多账号多端做端到端；设备与系统权限必须实机验证。假媒体适用于流程回归，不能代替真实音频、屏幕内容和系统权限验证。

建议质量目标（待 P0 测量后冻结）：受控正常网络下入会成功率 ≥99%，点击确认至远端首帧 P95 ≤5 秒，业务通知到 UI 更新 P95 ≤2 秒；网络恢复后的重连 P95 ≤10 秒。每次报告注明设备、系统、网络、人数和样本量，不把这些目标当现有实测结果。

## 6. 灰度与回滚

组织级 `meetingEnabled` 控制新入口和创建能力；可进一步按客户端版本限制。先测试组织，再小比例组织，监控入会失败、媒体质量、崩溃、提醒延迟、供应商用量和重复通知。

关闭创建开关不直接结束已在进行的会议，保留加入／恢复／结束服务到存量会话清空；安全事件可另设紧急停止并明确提示。回滚旧客户端时仍可识别会议消息并显示降级提示，后端 schema 保持兼容，不能回滚删除未完成预约。外部 RTC／IM 故障分别标记，避免笼统报「网络错误」。

## 7. 评审待定项和推荐值

| 待定项 | 推荐默认值 | 影响 |
| --- | --- | --- |
| 首期身份范围 | 同组织登录用户 | 外部访客会引入身份、链接授权和新安全边界 |
| 既有通话入口呈现 | 保留既有通话，新增会议入口 | Meeting 不使用 JuggleCall 已确认；入口布局和媒体互斥体验仍需评审 |
| 最大人数／可见视频路数 | 25 人／9 路作为验证目标 | 影响套餐、带宽、质量、CPU 和成本 |
| 普通成员邀请权限 | 默认允许同组织邀请，主持可关闭 | 影响主持管理和私密会议语义 |
| 会议聊天历史 | 会内独立记录，后入者可见本会历史 | 需要 IM 服务端权限支持与明确保留策略 |
| 预约开始规则 | 提前 10 分钟进入、等待主持开始 | 决定等待 UI、主持人缺席和提醒行为 |
| 日历范围 | 首期本系统会议日历 | 外部日历双向同步单独排期 |
| 平台范围 | 三平台验证；按已验收平台声明支持 | 系统音频与共享源选择尤其有差异 |
| 自动结束 | 空房 5 分钟；计划结束不强制挂断 | 资源回收和会议超时体验 |
| 数据保留 | 元数据／聊天 90 天、质量原始日志 7 天为候选 | 需明确组织策略、删除机制和存储成本 |
| 后端接口边界 | 现有云端组织服务扩展 | 仓库已确定为 jugglework-server；确认 API 与 RTC／IM 部署权限 |

评审先收敛身份范围、后端接口边界、IM 会内隔离和入口呈现；容量、阈值等可配置参数不阻碍方案阅读，但必须在发布前冻结并验证。

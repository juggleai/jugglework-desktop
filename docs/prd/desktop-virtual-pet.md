# JuggleWork 桌面虚拟宠物方案

适用范围：Desktop App。更新日期：2026-10-24。

本文件是唯一完整产品方案；[OpenSpec](../../openspec/changes/add-desktop-virtual-pet/)维护实现约束、验收场景和交付清单。文档目录不保存设计过程、重复审计、截图、动图预览或临时验证数据。正式图片保存在应用资源目录，验证结果由测试及构建输出提供。

## 1. 功能范围

- 左下角个人头像菜单在「检查更新」下方提供「显示虚拟宠物 / 隐藏虚拟宠物」，默认隐藏，记住本机偏好。
- 宠物是独立透明、置顶、可拖动的桌面人物。主窗口最小化、隐藏到托盘或切到其他应用后仍可使用。
- 右键菜单仅提供「重置宠物位置」「隐藏虚拟宠物」。
- 非拖动的机器人单击会显示并置前主窗口；点击任务卡片、输入目标或创建任务入口，导航成功后也显示并聚焦主窗口。编辑、语音、发送、停止和铃铛操作不置前主窗口。
- 功能包含人物动作、快捷输入、听写和任务提醒；不包含宠物商城、自定义上传、自动漫游、16向注视、文件附件或独立实时语音聊天。
- 常驻动画不调用模型；发送和听写复用应用已有服务。

## 2. 动作规则

| 状态或触发 | 动作 | 周期和行为 |
| --- | --- | --- |
| 显示、常驻待机、无任务、所有任务完成 | typing 打字眨眼 | 6帧，1560ms循环 |
| 输入、思考、输出、执行、重试、压缩、停止中、异常、卡住、录音和转写 | seated-working 坐姿工作 | 6帧，850ms循环 |
| 等待权限确认或问题回答 | waiting 等待 | 6帧，2120ms循环，优先于编辑和执行 |
| 鼠标从外部进入人物 | celebrate 小跳 | 5帧，1380ms一遍，完整播放两遍后回typing |
| 隐藏或退出 | 停止播放 | 不停止真实任务 |

人物动作、真实任务状态、面板开合相互独立。任务完成不触发庆祝；另有未完成任务时继续工作动作。部分项目不可用只披露同步范围，不凭空触发工作动作。

宠物编辑区打开即算编辑，无须先输入文字。主窗口只以可编辑的会话输入框实际聚焦为编辑来源；保存的草稿、设置页和其他编辑器不算编辑。

悬停覆盖任何基础动作，包括工作和等待。指针仍在人物上时，两跳结束后保持typing；离开时完成已开始的两跳，至少播放一轮typing，再恢复当前基础动作。再次进入的冷却时间为300ms，切帧和人物轮廓变化不构成新悬停。拖动、隐藏、休眠及减少动态效果可以取消装饰动作；减少动态效果使用对应动作的静态帧。

## 3. 人物、气泡和视觉

- 人物显示框104 × 112.67 DIP，保留蓝白机器人及带「Juggle」字样的电脑。
- 收起时在人物下方居中保留24 × 6 DIP小气泡，透明命中区40 × 20 DIP。有未读且未关闭的完成提醒时填充绿色。
- 人物悬停300ms、气泡悬停或点击后，气泡膨胀为工具条；离开整个交互区500ms且没有打开面板或聚焦编辑时收起。
- 大小气泡共用一个连续表面、同一中轴和上沿，上沿位于固定操作区起点上方6 DIP。宽高在260ms内变化，图标延迟80ms后用100ms显现；收起先淡出图标。快速重入从当前尺寸反向过渡。
- 工具条依次为编辑、语音、铃铛。有提醒时120 × 40 DIP，无提醒时隐藏铃铛和分隔线，居中收窄为80 × 40 DIP。
- 输入胶囊、卡片和菜单正文最大336 DIP；400 DIP画布两侧各预留32 DIP阴影空间。任务卡片使用独立淡阴影，最后一张更短、更浅；堆叠背卡不重复叠加阴影。
- 人物、气泡和面板使用独立定位。开合面板不重建人物、不重启动画、不改变人物屏幕锚点。
- 提醒区域展开与收起使用180ms淡入淡出。退出立即禁用交互，淡出结束才卸载；快速重开取消旧清理。减少动态效果时关闭过渡。

## 4. 快捷输入和目标选择

编辑按钮展开一条替换工具条的圆角输入胶囊：左侧加号、中间文本、右侧发送箭头。占位固定为「开始聊天」，英文为「Start chatting」，不随目标切换。输入区最小高40 DIP，文本最多增长至4行，超过后内部滚动；不显示原生拖拽柄。

任务提醒已展开时，点击气泡编辑入口保留任务面板及其展开状态，与输入栏同时展示。输入栏沿用单独打开时的定位，只按自身高度选择位置，不被任务列表的高度或展开方向推挤；任务面板独立定位，避开输入栏，空间不足时限高滚动。关闭输入或普通输入失焦后仍保留原任务列表。未打开任务时，进入输入栏不自动打开任务列表。

发送目标在胶囊上方独立展示「发送至 项目 · 会话」，过长省略，完整名称可查看。点击目标打开会话列表，不导航或唤起主窗口。

### 最新主任务

- 范围为当前账号、组织下全部可访问项目，排除子会话、已归档和已删除会话。
- 按服务端`time.updated`倒序，缺失时用`time.created`，同时间按稳定任务键排序。
- 开启空草稿时解析最新目标；有草稿时恢复原目标。解析期间可输入，按钮和Enter均不能向旧目标发送。
- 编辑期间固定项目和会话，后台更新时间变化不改发；只有用户明确选中另一会话才切换目标。
- 无可用目标时提供打开应用创建任务的入口，不自动创建聊天。部分同步或不可达范围必须显示提示。

### 目标行会话列表

- 点击发送目标展示跨项目的可发送主会话，包括没有活动提醒的历史会话，使用与最新目标相同的排序规则。
- 列表向上贴在发送目标行上方、向下贴在输入胶囊下方，等宽、间隔8 DIP，根据上下可用空间选择方向；空间都不足时限高滚动。两种方向均露出可点击的发送目标，打开列表不移动输入栏或人物。
- 使用24 DIP圆角不透明浮层，按工作区分组；工作区标题前使用与侧栏相同的文件夹/展开文件夹图标，默认展开最近更新会话所属工作区，各工作区独立折叠，可同时展开多个或全部折叠。展开后会话只显示文本标题，工作区和会话行保持清晰间距、保留胶囊选中态和细滚动条；正常列表最大高280 DIP。
- 所选会话在列表中标识，菜单不遮挡输入上方的目标提示。
- 选择后关闭列表、保留草稿、恢复输入焦点，后续发送固定到所选目标。录音、转写、发送或目标解析期间禁用目标切换。
- 加载、空列表、失败或部分结果均提供明确提示，不把读取失败表示成没有会话。

### 加号能力菜单

- 加号展示「插件」「MCP」「技能」三组，分组标题不带图标；条目以图标、名称和浅灰描述单行展示，描述超长省略，悬停或选中使用浅灰胶囊底色。有现成扩展图标时使用原图，否则使用文件图标。先展示本地扩展和技能，再补齐目标工作区的 MCP 服务及已分配云端技能；加载状态使用能力文案，不误写为会话。不可用的条目不允许选择。
- 选择能力后关闭菜单、保留草稿和目标并恢复输入焦点；所选能力复用列表图标，以蓝色文字进入输入胶囊内，不展示删除 ×。文字区开头按 Backspace 删除前一项；点击或方向键定位到能力项后可按 Backspace/Delete 整项删除。普通文字删除和输入法组合期间不误删能力项。选择新会话清除已选能力，避免跨工作区误用。
- 输入文字或选中能力即可启用发送，启用态使用蓝色圆形按钮和白色向上箭头；仅选择能力也可以发送。目标解析、发送、未知结果和语音期间仍按原规则禁用。
- 所选能力与文字、目标一起保存于主进程交互草稿，隐藏再打开不丢失；发送确认仅清理目标、文字和能力标识均未变化的原草稿。菜单关闭重开复用未完成请求，能力缓存立即展示并后台刷新；禁用技能及不满足连接、配置或工作区策略的扩展不可选，提交前再次校验。
- 提交时由目标工作区宿主重新校验所选能力并构造与主会话一致的能力指令和结构化草稿；PET 不持有服务令牌或业务客户端。能力发生变化时拒绝提交、保留原草稿。

普通快捷输入失去窗口焦点时收起输入和菜单，保留草稿及原目标；若原任务列表已展开，继续展示列表与工具条，否则收回小气泡。取消未执行的悬停回调，避免失焦后重新展开。输入内部焦点切换不收起。Esc先关闭菜单，再关闭编辑区，最后关闭提醒面板，不停止任务。

## 5. 发送、排队和未知结果

宠物页面只提交明确的目标、文字和所选能力标识。主渲染宿主使用目标项目的endpoint、模型、权限、配额、Connect维护和插件预检，不借用其他项目的当前会话上下文。

- 无活动运行且原队列为空时，经原会话发送路径提交。
- 目标运行中、正在发送预检或已有队列时，新消息排到原会话FIFO末尾；不能越过旧消息或阻塞队首，也不擅自改成插话。
- 队首失败保留完整草稿、附件和失败原因，停止自动消费；后续消息保持顺序。用户可在原会话编辑或移除阻塞项后恢复队列。
- 本地队列接收后显示「已加入队列」3 秒，提交错误提示也在 3 秒后消失；服务端接受后正常收起对应输入区，不显示常驻「已发送」提示。新的提交提示重新计时，目标加载等持续状态不受影响；预检期间显示准备状态。
- 气泡快捷输入确认发送或排队并清理原草稿后，收起输入栏、自动展开任务列表，将对应根任务置于首位并滚动到可见位置，不唤起主窗口。回执携带宿主确认后的任务投影，下一次任务广播接管实时进度；不虚构模型执行或完成状态。请求期间的新编辑、已切换的输入区和发送失败均不触发自动展开。
- 每个项目和根会话共用发送中及未知结果保护。快捷输入与卡片输入不能通过切换入口绕过保护；不同任务仍可独立操作。
- POST后网络中断、超时、宿主重载等无法确认的情况保留草稿并显示「发送结果待确认」。用户核对原任务后，明确点击「已核对，可重试」才解除对应任务的未知状态；不自动重发。
- 发送确认由主进程持有，隐藏、重开宠物页面不重置保护；旧页面草稿快照不能覆盖未知结果。
- 成功只清理同一目标、文字未变的原草稿，只关闭对应的原编辑区。用户已切换到另一张卡片或快捷输入时，延迟回执不能关闭当前编辑区；请求期间输入的新文字也保留。
- Enter提交，Shift+Enter换行，中文输入法组合期间的Enter不发送。失败保留草稿，不覆盖主窗口输入草稿。

## 6. 铃铛和任务卡

### 提醒集合和状态

一张卡对应一个根会话，汇总当前真实用户轮次及明确归属的后代活动。工具调用、重试和子会话不生成重复根卡。

提醒包括已知执行中、等待处理、待继续任务，以及当前主宿主生命周期内已关注任务的未读完成结果；不导入全部成功历史，不使用系统通知未读数。当前轮次以最近真实用户消息标识，纯草稿和未执行排队消息不产生新轮次。

| 状态 | 展示与操作 |
| --- | --- |
| 执行中、重试、压缩、有活动运行的卡住 | 共用会话状态/进度；跟进入原队列，可停止、打开和×关闭展示 |
| 等待权限或问题 | waiting动作；打开原会话处理，普通文字不代替审批或回答 |
| 已中断、失败、未完成、主动停止 | 坐姿工作；通过↩︎展开跟进输入，明确提交后继续原会话 |
| 主动停止已确认 | 标题前橙色点；停止中不提前标成已停止 |
| 状态确认中 | 保留原卡和草稿，禁用未确认的提交，读取恢复后重新分类 |
| 准备提交或正在停止 | 只表示局部操作阶段，不冒充服务端活动结果 |
| 已关注任务完成 | 绿色勾和原会话真实回复摘要；打开成功后将该轮标已读并移除 |

共享状态投影产生`statusText/progressText`，卡片与会话使用相同的工具活动、步骤、todo和异常语义；没有百分比不生成百分比。只使用面向用户的正文和可观察进度，不显示reasoning；仅有推理时使用todo或通用状态。字幕来自子会话时不改变根卡的跟进目标和停止范围。快照按请求前的todo版本回填，请求期间到达的实时进度优先；缓存快照不覆盖todo。

工具参数准备与实际执行按真实阶段区分：子任务启动前显示「正在启动子任务」，运行时显示「正在执行子任务」；命令执行前显示「正在准备命令」，运行时显示「正在执行命令」。当前工具详情优先于旧正文：委派显示 `Agent: 任务描述`，缺少描述时使用实际 agent 类型；命令显示经过既有脱敏规则处理的实际命令摘要，长内容省略。相同工具调用的旧快照不重复计数或复活终态。根任务等待子 Agent 时，宠物优先展示本轮正在执行的后代工具，等待权限/问题仍优先；任务完成后恢复真实回复摘要，不遗留执行中文案。

根卡片汇总本轮实际观察到执行或等待的后代结果。根会话已结束但本轮子任务被停止或失败时，卡片保留待继续状态，确认停止显示橙点，不标记绿色完成。子任务按观察时的根轮次及用户消息创建时间归属，根快照晚到也保留本轮已确认的中断；历史子任务结果不污染下一轮。

源元信息或本轮相关快照读取失败不能把卡片清空或假报完成。无关历史子任务读取失败只提示项目部分同步，不阻塞当前根任务的已确认完成。成功的权威快照解除临时断线原因，并恢复执行、待继续或完成状态；上一轮断线原因不等于当前连接不可用。快照返回时按会话更新时间与共享缓存核对，并保留请求开始时的单会话实时版本；请求期间到达的实时消息、结束状态和交互优先，旧快照及其缓存副本不能回填覆盖。失效缓存由新读取替换，新请求可恢复执行或确认下一轮。滞后快照不清除已知的用户停止事实，旧轮失败不污染新轮结果。

### 展开、计数和阅读

- 有可见提醒时显示铃铛与蓝色数量角标，超过99显示99+；无提醒不显示铃铛。
- 可见任务不超过3条时，点击铃铛直接展开完整列表；4条及以上先展示堆叠，前卡最大，其余提醒按真实数量逐张生成背卡，每层下移6 DIP并缩窄。堆叠本身不显示数字。
- 4条及以上点击堆叠再展开完整列表。工具条显示指向任务区域的箭头，无数量：任务在上方时向上、在下方时向下，随拖动及屏幕空间翻转同步更新；点击箭头关闭整个提醒区域，不先折叠成堆叠。
- 铃铛数为未读、未关闭的根任务提醒数，不重复计入子任务、草稿、准备阶段或系统通知。
- 点击执行中或待继续卡的标题只打开会话，卡片保留；只有×才关闭当前轮展示。×不停止任务，关闭记录在隐藏再显示宠物后保留；任务面板中的「重新显示任务卡片」可恢复关闭项，新轮次重新出现。
- 完成卡标题打开成功后将当前轮标已读并移出列表；打开失败保留，展开铃铛或编辑跟进不算已读。
- 确认完成后只保留提醒所需的展示事实，释放根会话及后代的宠物正文/快照观察者和活动跟踪引用；正文缓存回收不影响完成轮次和回复摘要，新任务开始时恢复跟踪。
- 在任务列表中点击×关闭最后一张卡片时，自动收起面板，收起箭头和铃铛位置一起消失，回到双按钮工具条。任务区和快捷输入栏下方不展示已关闭数量、重新显示入口或对应占位。其他原因导致提醒清空时，已打开的空面板仍保留收起箭头，不显示「暂无任务」提示。
- 编辑或指针停在列表期间固定卡片顺序，状态和进度继续更新；离开后按最近更新时间恢复排序。

### 跟进和停止

- 跟进、停止和×默认隐藏，仅当前卡悬停或操作按钮具有可见键盘焦点时显示；标题焦点或编辑本身不固定显示操作按钮。
- ↩︎只展开/收起该卡「继续跟进」输入，不导航、不自动发送。一次只展开一个卡内编辑区，切换保留各自草稿；没有独立「继续任务」按钮。
- 卡内非空输入通过Enter或发送箭头继续原任务，空输入不发送默认提示。接受后保留卡片和列表，仅关闭对应编辑区。
- 编辑期间任务完成时在原卡更新结果，保留未发送草稿。卡片已读、关闭或移除后收起原编辑区，不再因隐藏编辑区持续播放工作动作；非空草稿在任务面板和快捷输入下保留「未发送的跟进」入口，无铃铛时仍可通过编辑按钮恢复。恢复后固定原会话、禁用加号改发，不覆盖普通快捷输入草稿，也不新增提醒数量。
- 方块停止根及明确归属的后代活动，先清理其待发送队列，避免停止后队列自动重启。根idle不代表后代已结束。
- 停止回执只表示已请求；确认所有归属运行结束后再呈现终态。部分失败提示重试剩余活动目标，不能把自然完成误标成用户取消。

## 7. 语音

语音图标与会话输入栏共用可用性检查，未配置或检查中置灰，不请求麦克风。空快捷草稿检查全项目最新主会话所在项目，有草稿时检查其固定目标项目；实际启动前重新确认最终目标的配置，不复用其他项目的结果。检查期间取消、隐藏或切换上下文会使待启动请求失效。服务可用后由主渲染宿主持有唯一听写控制器及麦克风租约。

点击语音固定目标后开始听写；恢复已有草稿时直接使用其固定目标启动，不重新选择会话，不丢已有文字。沿用5分钟录音上限、20秒转写超时和现有权限/占用提示。转写只填入草稿，由用户确认发送；空结果不提交。取消、错误、隐藏、注销或上下文切换释放录音和麦克风。录音期间仍可停止或取消，不自动切换目标。

目标解析期间按Esc关闭输入、失焦收起或切换编辑入口会使待启动的听写失效，延迟目标回执不能请求麦克风或重新打开输入。取消后立即重开可共用未完成的目标读取，只有当前输入请求能启动听写；等待权限或连接时也允许停止和取消，不受启动请求的等待状态阻塞。

## 8. 原生窗口和布局

- 使用独立`pet.html`与唯一透明窗口；`frame:false`、`hasShadow:false`、`skipTaskbar:true`，无主窗口parent。
- 被动展示使用`showInactive`、`focusable:false`。明确点击输入、卡内跟进或语音后，仅宠物窗口取得键盘焦点；退出编辑后恢复被动。
- 同一显示器上使用固定宽`min(400 DIP, 工作区宽度)`、工作区全高的透明画布，面板开合不扩缩原生窗口。独立Electron session固定缩放1，不继承主窗口缩放。
- 约16ms采样拖动位置；超过5 DIP才认定拖动，松手先应用最终坐标再保存，同屏移动不resize。人物和气泡的拖动不能触发点击。
- 任务面板根据可用空间上下换侧，24 DIP缓冲避免临界点反复翻转，换侧使用140ms淡化。左右空间不足时与气泡对应边对齐，列表限高滚动。
- 加号菜单独立按输入胶囊选边。人物、当前控件、菜单和连接通道纳入原生命中；滚动裁剪之外、隐藏或不可交互的关闭按钮不纳入命中。滚动、悬停和焦点变化更新命中区域。
- 透明外围在编辑聚焦期间也允许鼠标穿透，点击其他应用可失焦。CSS透明不等同原生穿透；使用公开`setIgnoreMouseEvents`和稳定命中区域。
- 显隐及位置保存在`userData/desktop-pet.json`，字段为`schemaVersion/enabled/position`。草稿、轮次关闭/已读和未知发送状态驻留主进程内存，账号或组织上下文改变时清空。
- 主窗口隐藏不释放任务宿主。主动隐藏宠物销毁人物窗口、动画和宠物独有读取/监听，原任务及其队列不停止；主窗口实际销毁时同步关闭宠物。显式退出遵从原有文件保存与退出规则。
- 宠物崩溃不无限自动重建，菜单反映实际状态。主宿主重载后恢复任务事实，未知结果不自动重发。
- macOS应用级Cmd+H遵从系统隐藏行为，不宣称普通置顶窗口具备独立隐藏豁免。

主渲染宿主保留工作区及根/后代会话的同步引用，复用SSE和现有活动运行对账，不新增宠物业务进程、数据库、独立任务队列或第二份麦克风控制器。显示期间每10秒回补项目元信息；主会话元信息上限10,000条，达到上限披露部分结果。快照先读200条，缺少真实用户轮次时再补完整内容。

交互状态仅接受当前账号上下文的写入。延迟快照可补齐缺失历史，但不能覆盖较新的实时正文、停止信息或结束状态；删除及回退前的旧请求不再补历史。发送回执不能将已实时结束的任务重新标记为执行中。

图片路径统一为`apps/app/public/pets/juggle/{typing,seated-working,celebrate,waiting,fallback}.png`。每帧384 × 416；typing、seated-working、waiting各6帧，celebrate为5帧。帧时长在`src/pet/animation.ts`维护，运行时使用PNG图集，不用GIF控制两跳。

celebrate保持白壳、蓝色身体、青色眼睛和带Juggle字样的黑色电脑，起止帧保持站姿和相同的人物尺度。5帧头部宽度221原图像素，接地基线y=396，腾空脚底y=358；通过屈膝和实际离地表达小跳，不整体缩小人物。资源失败使用fallback，真实任务状态不受图片加载影响。

## 5. 最新代码静态审查：需验证的风险

下列是代码审查发现，不是本轮真机复现结论，也未修改实现：

1. **异步交叉结果可能过度撤层。** `meeting-annotation.mjs:115–160` 中静止 check 与工具切换导致的重新定位可能交叉；工具切换未必更新 placement revision。旧 check 在画布隐藏后失败，可能撤掉新定位。placement Promise 拒绝的 catch 仅检查 session，没有同等的过期 revision 判断。现有成功迟到测试不足以覆盖这两类失败路径。
2. **停止请求不等于退出确认。** `meeting-window-identity-windows.mjs:55–65`、`meeting-window-placement-windows.mjs:23–50` 以 kill/超时拒绝，但没有对外提供完整的退出确认。native watch 无 stdin EOF 协议；父端异常退出的清理需单独测试，不能拿替身的 kill 调用代替。
3. **身份认证仍有限制。** `MeetingWindowIdentityWindows.cs:38–65,140–185` 不保证识别同进程同线程的 HWND 复用；单个 HWND 消失只返回不可用，不算确认关闭。窗口关闭但宿主进程继续运行的可信关闭仍缺证据。本轮未完成该场景。
4. **层级只是非原子快照。** native place/check 仅操作自有画布，拒绝 topmost、非 96 DPI 和几何偏差；但点击、焦点或弹窗可在复核后改变层级。尚无普通非置顶遮挡窗下的真人输入证据。
5. **默认测试入口可能漏跑。** 本次新增 identity/placement 测试未纳入 desktop 默认测试命令；本轮已显式运行。annotation Windows 替身仍用简化目标，不能替代真实 string HWND → Node → native 的端到端会话。
6. **Windows 产品未接线。** `main.mjs:976–998` 仍以 macOS tracker 路径为主；开发 build 成功不代表新增 helper 被默认构建、打包或注入产品。

### 8.2 可重现运行器与更严格的判据

新增文件位于 `apps/desktop/scripts/`：


watch 取消及故障注入会调用 kill，但必须等待真实 close：只算**终止已确认**，不是原生优雅 EOF。`cleanup.forced` 指运行器等待超时后的兜底强制终止，另有 watchTerminations 明示主动终止调用。native watch 仍没有父端 EOF 协议；父端崩溃/被外部终止、生产适配器对外提供清理确认，仍未完成。

### 自有画布的原生消息对照

`--follow-observe-canvas-placement` 只在夹具自有 Electron 画布上计数 `WM_WINDOWPOSCHANGING` 和 `WM_WINDOWPOSCHANGED`，忽略参数，不读取指针，不装全局钩子。程序激活后的隐藏边界恢复收到 2 条 `changing`、2 条 `changed`，即时双向相邻与最终复核均通过（14.031 秒）。静态对照实际写入同样收到 2/2；紧接着对已经相邻的同一画布发起一次隐藏定位，复核通过且未走边界写入，收到 0/0；显示后复核通过（4.765 秒）。两轮清理确认、无残留子进程。

### 由画布所属线程发起定位的对照

隔离夹具 `--fixture-host-boundary-write`（须同时指定 `--fixture-adjacency-koffi` 和指针专用测试）只在暂停后的隐藏普通层顶部，将写入从原生子进程改为画布所属线程发起。写入前核对夹具窗口归属、线程、可见性、DPI、精确矩形与普通层边界；沿用默认 `SetWindowPos` 标志，不屏蔽位置通知，不操作目标或外部窗口。写入或即时读回不授权显示；仍需原生助手对隐藏画布做只读双向相邻验证，以及显示后的严格复核。

首次绑定初始化失败，清理确认，不计入对照。修正绑定后程序激活两轮（含一轮错峰重排）均确认实际走过宿主线程写入分支；回调两次读到双向相邻，返回后的即时读回同为 `both`，结束复核通过，清理确认且无剩余子进程（13.925、14.978 秒）。未验证真人首次点击路径；通过不能归因于线程差异，也不能认定故障已修复。此改动限夹具，Windows 产品入口仍关闭。

### 指针模式下的普通窗口遮挡：命中查询与实际点击分开验收

## Context

Web 管理台配置存储，control API 决定谁能上传，七牛接收文件，桌面端把已上传文件的 URL 写入现有业务记录。签发、上传、保存业务记录是三个独立步骤；任一步成功都不能作为下一步成功的凭据。

## Goals / Non-Goals

- 目标：按组织隔离配置与签发，按用途限制文件，沿用现有用户资料和任务 Markdown 数据格式。
- 非目标：私有桶签名下载、按任务 ACL 鉴权下载、群头像迁移、对象杀毒、自动回收弃用文件，以及变更桌面安装包的分发渠道。

## Decisions

1. **由组织管理台保管配置。** `GET/PUT /jwork/api/v1/storage/settings` 使用会话的活动组织，而不是接受任意组织 ID。仅该组织 owner/admin 能管理；数据库每组织一行，Secret Key 绑定组织加密保存。管理台只知道是否已有密钥，留空即可保留。这样不必在每台桌面分发长期密钥。
2. **服务端签发，不代理字节。** Den 客户端向 `POST /jwork/api/v1/organizations/:organizationId/file-upload-credentials` 提交 `purpose`、`fileName`、`contentType`、`sizeBytes` 和可选 `taskId`。服务端从已认证身份导出组织和用户；指定任务时检查任务权限。服务端生成 UUID 对象名，签名覆盖完整 `bucket:key`，而非整个目录。用途、大小、类型和 key 格式详见 `specs/organization-file-storage/spec.md`。
3. **直传与业务写入分开。** 签发返回 `provider`、`uploadUrl`、`token`、`key`、`fileUrl`、`expiresAt`；renderer 直接 multipart POST 到七牛官方上传域，不用带登录态的 Den 传输。回执 key 与签发值一致后，头像用 `avatarUrl` 更新本人资料；编辑器在原选区插入带 `"task-file"` 标题的 Markdown。任务创建、描述保存和评论发送仍走各自的业务接口，无需附件表。草稿创建任务时保留原 URL，不移动对象。
4. **下载域与业务域分离。** `fileUrl = downloadBaseUrl + "/" + key`，没有下载签名。采用非私有桶和独立、无业务 cookie 的 HTTPS 域名，避免把上传内容放在业务站点的信任范围内。随机 key 降低猜中概率，但不赋予访问控制；需要逐次授权的组织应保持禁用。
5. **对象只按业务用途分目录。** 新对象使用 `avatars/`、`images/` 或 `attachments/`。短头像对象名带服务器签名标签，用于核对活动组织、用户、下载基址和文件名，避免接受别人的头像；原本人头像路径仍兼容，旧对象及 URL 不迁移。目录不替代组织选择与任务鉴权。

## Risks / Trade-offs

- **链接外传** → 管理台启用前说明持链接可读，私密任务和未保存草稿也适用。移除成员、删除任务或关闭开关都不会撤回已有链接；要下架文件需处理桶对象及 CDN 缓存。
- **上传成功但业务保存失败** → 不显示资料保存或评论发送成功；桶内可留下无引用对象。运维不能按目录推断对象未被引用，旧 `draft/` 对象也可能被已保存的任务引用。
- **不可信文件或错误端点** → 图片限制扩展名、大小并检测 MIME。通用附件使用随机 `.bin`；七牛凭据不带 `mimeLimit`，以 `detectMime=-1` 使用客户端声明的二进制类型。下载域须与业务站点隔离，核对禁目录索引、`nosniff` 和附件响应头。上传不等于恶意内容扫描。
- **客户端上下文变化** → 取消或忽略迟到结果，避免切换账号、组织、任务或编辑位置后误写；回执不符时不写 URL。

## Migration Plan

1. 应用服务端迁移 `2026112201.sql`，配置服务器加密密钥与 key ID，部署 control API、管理台和兼容桌面端。未配置组织保持禁用；旧 `avatarDataUrl` 接口仍为 2 MiB，群头像仍走 IM 托管 URL 校验。
2. 用无敏感数据的验收组织按 `tasks.md` 的生产联调清单检查真实桶区域、CORS、下载域及三个业务入口，留存脱敏结果后再决定推广。
3. 上线前核对新旧前缀的桶权限与 CDN 规则；避免混用仅接受旧头像路径和签发短路径的 Server 实例。回退时保留下载域和仍被引用的对象；已保存链接仍有效，尚未保存的短头像需重新上传。

## Open Questions

真实桶的区域端点、打包桌面端 Origin/CORS 和 CDN 实际响应尚未端到端验收。组织可接受的公开读取范围、对象保留期及缓存清理责任人需在生产启用前确认。

## ADDED Requirements

### Requirement: 直传成功并核对回执后引用
桌面端 MUST 按用途检查非空文件名、MIME 和字节数；使用登录态向活动组织请求凭据，再通过独立请求上传文件。只有上传成功并确认回执后才可使用 `fileUrl`。

#### Scenario: 上传一个文件
- **WHEN** 收到未过期的七牛凭据、允许的官方 HTTPS 上传端点和有效 HTTPS 文件 URL
- **THEN** 向 `uploadUrl` multipart POST `token`、原样 `key` 和 `file`；不带业务 cookie、登录 token 或 referrer，不跟随重定向。HTTP 成功且 JSON 回执的 `key` 与签发值相等才返回文件 URL。

#### Scenario: 上传未获确认
- **WHEN** 签发失败、凭据无效或已过期、上传失败、回执缺失或 key 不匹配
- **THEN** 不写用户资料、不插入 Markdown；编辑器保留原文并提示失败。

### Requirement: 头像写入本人资料 URL
桌面端 MUST 以 `avatar` 且不带 `taskId` 上传选中的头像，随后通过 `PATCH /me/profile` 的 `avatarUrl` 更新当前用户资料。

#### Scenario: 更换头像
- **WHEN** 回执匹配且仍是发起上传的账号和组织
- **THEN** 提交返回的 URL，不提交图片字节或 `avatarDataUrl`；资料保存成功后使用服务端返回的用户资料刷新头像。

#### Scenario: 资料上下文已变更
- **WHEN** 上传结果返回时用户已切换账号或组织
- **THEN** 不将原请求的头像写入新上下文；群头像不进入此流程。

### Requirement: 图片与附件进入任务 Markdown
桌面端 MUST 在可编辑描述和可发送评论中提供图片及附件入口。图片入口生成 `![文件名](fileUrl "task-file")`；附件入口生成 `[文件名](fileUrl "task-file")`，包括以附件方式选择的图片。文件名中的 Markdown 分隔符按文本编码。

#### Scenario: 新建草稿与已保存任务
- **WHEN** 在新建或已有任务的描述编辑器、或任务评论编辑器中点击图片图标
- **THEN** 直接打开系统文件选择框，工具栏保持可见，不显示图片地址输入框；仅接受 PNG、JPEG、WebP、GIF 图片，每张不超过 5 MiB。
- **WHEN** 在新建任务描述中选取文件
- **THEN** 省略 `taskId`，将服务端返回的 URL 加入草稿描述；只有创建任务时才随正文提交，不预建任务或搬移对象。
- **WHEN** 在已有任务的描述或评论中选取文件
- **THEN** 传入真实 `taskId`；描述沿用原保存流程，评论只在发送时提交。再次打开正文可预览上传图片或通过文件名打开附件。

#### Scenario: 任务附件卡片与下载
- **WHEN** 从任务或评论的回形针选择附件
- **THEN** 文件选择框不限制格式。对有名、非空且不超过 20 MiB 的文件，无论浏览器是否识别扩展名，均以二进制附件上传，卡片和下载使用原文件名。
- **WHEN** 在任务详情中展示描述里的附件引用
- **THEN** 在描述下方独立显示附件数量、文件卡片和下载全部；所有大小已知时显示总大小。未记录大小的旧附件不计作零字节。可编辑用户直接通过系统选择器继续添加；正文插图和评论附件不计入此区域。

#### Scenario: 已添加附件的单项操作
- **WHEN** 任务详情展示已添加的描述附件
- **THEN** 卡片右侧依次提供带可访问名称的预览、原名下载和移除图标；只读或仅可评论成员没有移除入口。
- **WHEN** 用户预览图片、音视频或文本附件
- **THEN** 在对话框预览支持的格式；不支持、过大或加载失败时提示下载，不执行附件中的标记或脚本。
- **WHEN** 可编辑成员确认移除一张附件卡片
- **THEN** 只用任务当前版本移除这一次引用；取消、失败或版本冲突不会静默删除文件，其他引用和云存储对象不受影响。

#### Scenario: 评论附件从草稿到发送
- **WHEN** 通过评论附件入口上传成功
- **THEN** 在正文与工具栏之间显示可移除的文件卡片，不在正文内重复显示文件名。允许仅发送附件；上传中不能发送，发送失败保留草稿供重试。
- **WHEN** 展示已发送评论
- **THEN** 每个附件只在所属评论正文下方显示一张可下载的卡片；识别 `task-file` 和含字节数的 `task-file:大小`，旧附件显示大小未知。正文插图、普通链接和代码示例不列入卡片。

#### Scenario: 评论权限不允许修改描述附件
- **WHEN** 成员有评论权限但没有内容编辑权限
- **THEN** 可在评论插入上传结果，描述保持只读。

#### Scenario: 延迟结果不污染正文
- **WHEN** 文件选择取消，或等待上传期间原编辑器、任务或插入位置已失效
- **THEN** 不插入迟到的文件引用，也不因为打开选择器而提前创建任务、保存描述或发送评论。

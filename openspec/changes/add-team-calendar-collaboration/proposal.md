# Proposal

## Why

个人日历无法支持团队排期、共享可见性和参会协调。完成核心日历与办公体验后，需要在既有组织成员与权限模型上增加团队日历、忙闲查询和邀请响应，同时保证私密日程不会因协作功能而泄露。

## What Changes

- 在前两阶段稳定后，新增组织团队日历和 `free-busy`、`viewer`、`editor`、`manager` 分级权限。
- 新增日历成员管理、授权变更事件、撤权后的缓存失效和权限过滤增量同步。
- 新增日程参与人、邀请、接受/拒绝/待定、更新与取消通知；日历成员与日程参与人保持独立模型。
- 新增组织内忙闲查询、排期冲突提示和共同可用时间建议；无详情权限时只能返回忙闲块，不能泄露标题、描述或参与人。
- 新增团队日历管理、成员权限、参与人响应和排期辅助的 Desktop 体验与相应 Agent 能力。
- 本阶段不支持跨组织/外部联系人邀请，不创建视频会议，不预订会议室，不提供对外预约页面，也不接入外部日历供应商。

## Capabilities

### New Capabilities

- `team-calendar-sharing`: 组织团队日历、分级角色、成员管理、撤权和权限安全的多端同步。
- `calendar-attendance`: 组织内参与人邀请、响应、更新、取消和通知语义。
- `calendar-availability`: 隐私安全的忙闲查询、冲突提示和共同可用时间建议。

### Modified Capabilities

无。

## Impact

- 前置条件：`add-cloud-calendar-core` 与 `add-calendar-work-planning` 均已实施并通过权限、同步、重复与提醒验证。
- `jugglework-server`：新增日历成员、参与人、响应、授权事件、忙闲查询与团队通知 API。
- `jugglework-desktop`：新增团队日历设置、共享成员管理、参与人选择/响应和排期建议界面。
- 安全边界扩大到对象级字段遮蔽、撤权缓存清理和组织成员失效，需要独立安全审查与多成员集成测试。
- 本变更为后续会议、会议室和预约能力提供参与人及忙闲基础。

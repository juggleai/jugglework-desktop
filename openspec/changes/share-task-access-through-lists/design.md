# Design

## Context

当前多清单关联保存在 `product_task_filings`，旧 `list_id` 仍参与授权。更新清单可见性时仍检查旧归属任务的 `visibility`，因此会拒绝部分 `private → members` 的协作人更新。`add-cloud-tasks` 仍未归档；这次变更单独规划新的授权模型。

## Goals / Non-Goals

**目标：** 服务端统一计算任务读写权限，将直接授权与各清单派生授权合并；多清单仍引用同一个任务，任务编辑权限不等于管理权限。

**非目标：** 不引入飞书群、文档或子任务的继承机制；不自动给任务添加成员或负责人，不让任务链接反向授予任何清单权限；保留「所有负责人完成」的逐人确认语义。

## Decisions

1. **直接授权与清单角色按操作取并集。** 保留任务创建者、直接成员和既有组织级授权；未分享不等于组织公开。新清单上，`member` 保持 wire 格式，映射为可阅读；`administrator` 映射为可编辑；所有者可编辑和管理清单。任务编辑包括内容、日期、负责人和完成/重启，但不授予管理单独分享、删除、恢复或替其他人完成签核的权限。阅读可评论，不意味着能修改任务字段。API 逐个过滤不可访问的清单身份。
2. **启用后的清单以实际关联授权。** 通过 `product_task_filings` 动态授予权限；不会复制永久任务成员。旧 `list_id` 只保留兼容，历史未启用的清单继续使用旧权限。保留一个任务 ID、版本和完成状态；读取按任务去重，归档不撤权。继承编辑权不开放回收站。
3. **展示并校验读者与编辑者变化。** 新规则下，归类要求任务编辑和目标清单编辑权限；新增可以独立持续的授权来源还需任务分享权限，放入有其他受众的清单须明确确认。修改清单成员或启用历史清单时也检查相关任务；首版保守要求变更人拥有受影响的任务，不在分享成功后静默隐藏部分任务。清单确认绑定版本及受影响任务集合；旧客户端不能绕过。普通指派权限与任务查看人、关注人及可见范围管理分开；指派可以授予对应负责人的直接访问权。
4. **所有读取面使用同一判定。** 任务分页、搜索、详情、活动及相关深链接统一检验，不只在清单页过滤；计划检查评论、附件和通知的现有独立权限。权限变更后刷新 Desktop 列表及详情，旧缓存不可作为授权依据；仅有清单查看权不自动订阅任务或广播历史活动。

### 与尚未归档的 `add-cloud-tasks` 的协调

| 现有条款 | 本变更的替代规则 |
| --- | --- |
| `Cloud-authoritative tasks`、`Task fields and lifecycle`、`Task visibility and authorization` | 仅保留一种任务模型，使用直接权限与清单派生读写权限；其他任务字段、生命周期不变。 |
| `Organize shared tasks without sharing the destination list` | 保留“不反向分享目标清单”的边界；不再以任务创建人或任务类型决定能否归类。 |
| `Independent task filings`、`Filing preserves direct sharing` | 保留独立多清单关联，派生授权不改写任务的直接分享。 |
| `Preserve legacy list-derived authorization` | 上线兼容期使用旧授权对照；启用后按当前关联评估，不保留失效关联的访问权。 |
| `Append collaborators on confirmation` | 保留角色值、版本和确认流程；按所选角色提示已有与未来任务的读写权限。 |

两端尚未归档的 `add-cloud-tasks` 权限条款已按上述对照同步；不改动无关功能。

## Risks / Trade-offs

- [历史归类静默扩大读写范围] → 存量清单默认不启用归类授权；核对新增读者和编辑者，经有权人员确认后整张清单切换。
- [原本依赖旧清单管理角色的任务删除/恢复/分享权限发生变化] → 历史清单启用前保留旧行为；启用时告知编辑不等于管理，不复制成永久直接授权。
- [服务端与 Desktop 版本不一致] → 用能力声明控制新界面；兼容字段留在过渡期，只在已确认的授权模型下执行可扩大访问的写入，不以字段迁移触发分享。

## Migration Plan

1. 先在测试环境核对旧归属已回填为清单关联、单独授权和组织边界；输出匿名化的访问差异和有影响清单数，不记录任务正文或私密清单内容。
2. 保留任务数据和兼容字段，逐环境启用服务端能力，再开放 Desktop 新界面。对历史扩大受众的清单，在授权确认前保持旧行为。新建或首次分享的清单按新规则，并在分享时明确受众影响。
3. 验证类似 `TaskGroup` 的实例能分享，且查看与编辑权限分别符合预期。需要回退时停用新权限入口并按环境保守关闭派生读取，核对已确认记录；不删除任务和现有直接共享，也不假定能收回已被查看的信息。

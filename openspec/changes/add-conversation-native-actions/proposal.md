# Proposal

## Why

用户希望在 Desktop 任务会话中直接查询和处理 JuggleWork 原生待办、联系人、日历、会议和 IM，而无需切换工作页面。这些业务已有独立入口，但需要为会话助手提供按当前登录人权限执行的结构化能力，并避免误发邀请或消息。

## What Changes

- 首期提供原生待办和通讯录的只读查询；明确「我今天到期的未完成任务」的身份、状态和日期口径。
- 增加创建原生日程、创建即时或预约会议、向明确的单聊或群聊发送纯文本 IM 的会话能力。用户在执行前查看并批准目标、内容和外部影响；可组合操作逐步返回结果。
- 复用现有 Desktop 登录会话、业务接口和权限审查；能力不依赖当前任务页、日历页或 IM 聊天窗口。
- 不开放通用 REST、SDK 透传、云端无人值守、外部 MCP、批量发信或自动入会。不改变已有任务、日历和 IM 页面行为，也不覆盖外部连接器。

## Capabilities

### New Capabilities

- `conversation-native-actions`：Desktop 会话发现和调用原生业务能力，以及只读查询、精确确认与分步骤回执规则。

### Modified Capabilities

无。

## Impact

- `jugglework-desktop`：会话工具发现与宿主执行、原生领域适配器、确认卡与结果呈现、权限和联调验证。
- 复用现有任务、日历、会议、联系人和 IM 接口；不计划变更 `jugglework-server`、数据库或公开 Connect/MCP 能力目录。若联调发现必要的服务端契约缺口，应另立关联变更，不在此变更中绕过权限。
- 独立于 `add-cloud-tasks` 的核心任务功能，以及现有会话工具权限模式。

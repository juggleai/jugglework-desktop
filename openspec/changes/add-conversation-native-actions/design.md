# Design

## Context

原生产品入口已经各自实现。任务和日历使用 `DenClient`；会议复用已有会议和日历预约契约；联系人和文本消息复用现有 JuggleChat 数据与客户端。`add-cloud-tasks` 不包括任务助手，本变更也不修改会话内部 Agent Todo。更多任务日期和过滤背景见此前的 `task-conversation-query-design.md`。

## Goals / Non-Goals

**Goals:** 用同一宿主能力层承载只读查询和需确认的命令，复用业务权限和现有 UI 缓存更新路径，在 dev 和打包应用中验证真实会话调用。

**Non-Goals:** 不把工具变成通用 HTTP/SDK 代理；不依赖模拟点击；不把已授权的外部 Connect 能力混同于原生能力；不新增业务数据库表或改变现有会话授权模式。

## Decisions

### 1. 宿主注册固定能力，不跟随页面

沿用语义查询/命令发现机制，拟用 `product_tasks.list`、`contacts.search`、`calendar.prepare_create`、`meetings.prepare_create`、`im.prepare_send`。在会话可用的全局 Desktop 宿主注册，而不是在 `TaskPage`、会议页或某个聊天窗口挂载时注册。工具 schema 不接受任意组织、服务地址、凭据或 API 路径。宿主从受信运行上下文推导作用域和调用来源；如果当前桥接不能证明调用属于原会话，先补调用上下文，不能退回到前台窗口身份。

### 2. 查询按日期和权限约束返回

待办默认映射到 `listProductTasks` 的 `view=assigned`、`status=todo`，使用 `dueAtFrom` / `dueAtBefore`，按 `due_at` 升序，不用会额外纳入逾期和今天开始任务的 `view=today`。用设备本地日历计算两个零点，不用固定 24 小时。续页绑定同一个日期范围和作用域，首批默认 20 条并有硬上限。仅投影编号、标题、截止时间、优先级及可用详情入口；日期型任务不因当天零点被误标逾期，明确指出原数据没有独立日期精度时的限制。通讯录返回有权限的少量候选及不透明选择引用，不把整本通讯录或私密字段发给模型。

### 3. 预览不写入，确认由用户界面执行

```text
解析请求 → 只读核对候选/权限 → 生成不可变提案 → 显示确认卡
   → 用户取消/提案失效：无写入
   → 用户确认：重新验证上下文和目标 → 按原值执行 → 返回逐步回执
```

写类工具只准备提案，不提供 `confirmed: true` 类参数。宿主持有短期、一次性确认记录，绑定会话、账号、组织、规范化参数和动作；确认卡可显示内容，执行时按记录取原值，不能由模型替换。日历预览目标日历、标题、时区、开始/结束、邀请对象和通知影响；会议预览即时/预约、时间、时长、对象和通知路径；IM 预览实际会话与完整正文。登录状态、权限、目标或计划变动时重新准备，不复用旧确认。采用宿主业务确认，而不是泛用的工具权限弹窗，以免 `Full access` 或历史授权变成发消息的认可。

### 4. 执行走原模块，确认可核对的事实

源模块成功回执作为结果依据，不把 `pending`、网络超时或“进入页面”当成成功。日程邀请和会议通知不混同于创建本体。组合操作只允许有明确定义的依赖，例如先创建会议、再把真实链接代入已展示的 IM 模板；模板、收件人或副作用发生实质变更时重新确认。保留领域已有幂等键或消息事务 ID；无后端幂等或查询核对能力的动作，用本次确认去重并在超时后返回“结果未确认”，不承诺跨重启恰好一次。已生效的步骤不自动回滚。

## Risks / Trade-offs

- [双栏、账号切换或权限撤销] → 绑定原会话和组织；执行前复核，查询返回前再检查，已发出的写入不可假称撤销。
- [以姓名或当前窗口推断目标] → 同名要求明确选择；群聊单独解析，不从当前聊天自动取目标。
- [数据进入对话模型和会话记录] → 只投影必需字段，标题/消息内容视为数据，不自动进 Memory Bank，遥测不记业务正文和凭据。
- [部署能力有差异] → 按安装版本、连接状态和权限暴露能力。预约或邀请等操作缺少现有契约时标记不可用，另立服务端变更，不私下取凭据补齐。

## Migration Plan

无需数据迁移。先在已连接的本地 Desktop 会话验证只读能力，再分别启用日历、会议及 IM 写能力。用测试组织和测试收件人验证新建、取消、重复确认、超时和部分成功。可关闭新增能力入口停止后续调用，不删除已经创建的业务记录。

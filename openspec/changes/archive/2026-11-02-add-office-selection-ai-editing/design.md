# Office 选区 AI 编辑设计

## Context

已有实时选区、同模型内容工具和统一保存。现有动作解析当前活动文档，不能直接执行固定选区标签。首版未发送草稿绑定一个选区文件，切文件前确认清理选区。详细数据契约、交互、格式限制及验收定义由 `docs/office-selection-ai-editing-design.md` 统一维护。

## Goals / Non-Goals

目标是页内添加/发送、三种输入栏标签与卡片、绑定本轮选区的内容修改、两个宿主一致及跨平台能力开放。

不新增 Agent 文档创建、在线文档服务、SDK 在线 AI、文档协作引擎、全局选区轮询或跨文档事务。未关联聊天的系统打开文件不自动选择最近聊天。

## Decisions

1. 采用项目维护的 SDK 页内浮层与本地 Agent；添加和发送是明确动作，普通选区变化不直接改写草稿。
   浮层为紧凑输入框和单个圆形确认按钮，不提供关闭图标或下拉箭头；悬停确认按钮或键盘聚焦操作区时显示添加/发送方式。点击外部收起未提交浮层并释放候选，迟到采集回复不得重新弹出。
2. Server 生成引用并持有模型归属；显示文字、路径、时间戳和页面 fileId 不决定执行目标。
3. 指令组使用 Lexical 可编辑段落，只有选区标签是原子节点，要求文字与主输入栏共用光标、选区和历史，不使用嵌套输入框。换行和粘贴保持指令组归属，行首标签删除后光标回上一段末尾，复制使用可读标签和完整要求。已释放引用不能通过撤销恢复执行权限。
   Lexical 标签与 `office-selection` part 关联 referenceId，指令组用 instructionId 明确关联要求和引用；消息与队列携带显式引用列表，历史标签仅供展示。
4. Server 接收消息时确定目标模式；选区轮次的 `office.tools`、写入与保存必须使用有效 selectionRef，缺失或未知轮次归属时拒绝。没有选区的普通轮次保留原规则，不按 Agent 是否传引用临时选择模式。
5. 按已验证工具映射约束写入范围，不用通用字段猜测。未知工具与越界修改拒绝。
6. 无可靠内容版本时使用模型语义摘要。内容变化、恢复和重新导入使引用失效；不做自动模糊重定位。
7. 同一用户轮次、文档和模型代次共用执行状态；各覆盖域共享已确认基线，各引用保留自己的范围。坐标改变要求已验证新范围或宿主完整计划，未具备时要求拆分；已发送任务始终绑定原模型。
8. PPT 文字范围格式与整框替换分别开放，局部文字保真替换未适配时不执行扩大范围的替代写入。
9. 文件目标改变前由应用级入口检查草稿；确认仅清理未发送选区标签，普通文字和附件保留，关联修改要求转为 needs-selection 并阻止发送。失败、取消不清理，同文件迁移及聊天切换不误清理。多文档选区草稿属于后续范围。
10. 独立窗口检查同一聊天草稿，系统打开与原生快捷键不能绕过；弹窗使用原生系统模态框，位于原生编辑页上方，保留页面和模型存活。
11. 原生输入提交、范围及同状态证明均在浮层聚焦前完成；添加/发送消费冻结结果，不重读当前光标。不能证明原范围时要求重选。
12. 八类选区分别映射到明确的 SDK 工具参数，宿主派生和校验定位，完整内容证明与截断预览分开；行列意图未确认不允许维度删除。
13. 写入后回读同模型目标并核对实际效果，再更新共同基线、保存及报告。超时可能已写入时暂停核对，不自动重复执行或吸收未知变化。
   公式核对仅规范化前导等号及函数名大小写，保留字符串、带引号名称、结构化列名及单元格引用，原始输入和回读值不改写。
14. 复用 admission 的实际用户消息与 assistant parentID 归属，普通 prompt、队列和 steer 一致；定位高亮与写入授权分开，不能用视觉当前选区决定编辑目标。
   客户端发送中请求独立持有本次引用，持有从异步预检前开始，到接收结束或队列接管后结束；输入栏删除不能提前释放，成功、取消和失败均结束临时持有，仅释放没有其他所有者的引用。
   主动删除最后一个选区标签代表明确取消该组的选区上下文，要求保留为普通文字，不额外显示重选操作；系统清理和模型失效仍保持待绑定状态，不能隐式转投新文件。
15. Word 连续跨段选区保留中间分隔符和空段；模型读取完整所选段落，宿主适配同段数的改写并倒序调用段内替换，格式操作只处理正文。修改前完整预检，修改后核对版本、文字、坐标、未选字符格式及段落属性；部分失败暂停，不重试或确认保存。段落合并、拆分、复杂结构不在当前范围。

## Risks / Trade-offs

SDK 原生 UI 和回调按格式核对，不能由已有 PPT 配置推定其他格式就绪。版本能力不足时语义摘要有本地读取成本，需有明确资源预算和失败行为。跨窗口迁移沿用既有平台边界，不能把资源齐全当作实机通过。

## Migration Plan

先完成共享桥与固定引用，再接输入栏，最后接本轮执行和保存。桥与格式适配就绪前维持原有入口状态。新规范只替换对应 PPT 入口场景，不改写旧任务的已完成事实。

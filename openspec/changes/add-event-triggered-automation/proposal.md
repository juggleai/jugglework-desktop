## Why

`add-local-automation-tasks` only accepts a clock as a trigger. Users need automation to react to what other people do on GitHub — a PR opened, a review comment left, an `@` mention — without babysitting notifications and manually starting a session. Full product rationale, competitive positioning, user scenarios, and UX detail live in `docs/event-triggered-automation-prd.md`.

## What Changes

- Add `事件触发` as a second trigger kind in the automation editor, alongside the existing `定时` tab group, with its own configuration flow (connector, repository, event-type matrix, advanced filters, delivery-mode selector).
- Extend the automation trigger contract from `AutomationSchedule` alone to `AutomationSchedule | AutomationEventTrigger`, reusing existing lifecycle, permission, connector-allowlist, and run-record infrastructure unchanged.
- Auto-tier the permission profile by repository visibility: public repositories force the restrictive read+comment tier by default; private repositories keep the existing two-tier choice. Event body text (PR/issue titles, descriptions, comments) is wrapped as untrusted data in the assembled prompt, never as instructions.
- Add device-side self-trigger suppression (drop events authored by the automation's own GitHub App identity) and per-entity debounce (`concurrencyKey`, default the PR/issue number) so rapid-fire events collapse into one run.
- Reuse the existing local executor/session-creation path for event-triggered runs, with one entity-scoped exception: successive triggers for the same `(automation_id, entity_ref)` (e.g. the same PR across its open/review/update lifecycle) reuse the same OpenCode session instead of each creating a new one, so a re-review turn continues the prior conversation rather than starting over. Scheduled runs are unaffected — this only changes event-triggered dispatch.
- Make offline backlog drops visible: when the server-bounded delivery window expires before a device claims it, record a `skipped` run history entry (`event_backlog_dropped`) with a count and time range instead of silently discarding it.
- Add inline guidance when the owning organization has not installed the GitHub App or the target repository is not yet bound as a connector instance, so the editor never dead-ends without a next step.
- Add a pre-enable cost/frequency estimate and an optional per-hour trigger cap, surfaced in run history as `rate_limited` when exceeded.
- Add a delivery-mode control (`自动` / `强制 IM 推送` / `强制轮询`) that defaults to the best available channel reported by the server readiness probe.
- Add `"github-app"` as a new `AutomationConnectorSelection.source` value, distinct from the personal `local-mcp`/`cloud`/`directory` connectors, representing authority to act on GitHub as the automation's own App identity via a per-run, server-minted, time-limited grant — resolving a previously undefined gap where self-trigger suppression compared against an "App identity" that nothing actually authorized the device to post as.
- Fetch a fresh run-bound write-back authorization at the preflight step of every event-triggered run, including every continuation turn dispatched into a reused session (§ session-reuse), not once at session creation; attempt exactly one silent re-fetch on a mid-run expiry before failing that write-back action; map acquisition failure onto the existing `connector_unavailable`/`connector_reauth_required`/`connector_scope_unavailable` error codes rather than inventing new ones.
- Extend session-affinity upstream-invalidation triggers to include repository transfer (not just unbind/uninstall), since it revokes the same connector binding without any explicit action inside this product.
- Fix restart reconciliation for a reused session: a session's idle state after restart can mean either "the prior turn finished normally" or "this turn's prompt was never actually dispatched before the crash" — reconciliation must distinguish the two by correlating the run's dispatch record against the session's own message history, not treat idle as always meaning "done."
- Order delta-aware prompt assembly (§ session-reuse) by each event's own GitHub-reported timestamp, not by device arrival order, since GitHub does not guarantee webhook delivery order.
- Structure advanced filters as a common set (author, label, mention, keyword — applicable to any future event provider) plus a GitHub-specific extension (branch, path), instead of one flat GitHub-shaped filter object, so a future non-GitHub provider extends rather than restructures this data.
- Resolve permission tiering through an intermediate `inputTrustLevel` (`open`/`restricted`) rather than reading GitHub repository visibility directly in shared tiering logic; the GitHub adapter maps visibility to this level.
- Allow a draft blocked on "App not installed"/"repository not bound" to persist locally in an explicit resumable state (not requiring full validation to save), and notify the requesting user when the server-reported readiness for their blocked repository flips to ready — closing a gap where a delegated (non-admin-self-service) installation/binding request otherwise loses the user's in-progress configuration and never tells them it unblocked.
- Extend session-affinity invalidation (see the entity-session-reuse requirement) to explicitly distinguish "the mapped session is unresolvable" from "the mapped session's underlying connector/repository binding was revoked," surfacing a distinct error code for the latter.

## Capabilities

### New Capabilities
- `automation-event-trigger-config`: Event-trigger editor UX — connector/repository selection, event-type matrix, advanced filters, delivery-mode selector, permission auto-tiering, cost/frequency estimate, and inline App/repo-binding guidance.
- `automation-event-trigger-execution`: Device-side event consumption — delivery-channel client (IM push consumption + polling fallback), self-trigger suppression, per-entity debounce, untrusted-content prompt wrapping, offline-backlog visibility, and rate-limit enforcement, feeding the existing executor.

### Modified Capabilities
None. `automation-management` and `automation-session-execution` are still defined only inside the sibling in-progress change `add-local-automation-tasks` (not yet archived to `openspec/specs/`), so this change cannot express a formal delta against them yet. Once that change archives, a follow-up delta must add: a trigger-kind selector and `AutomationEventTrigger` validation to `automation-management`, and `event` as an `AutomationTriggerSource` value plus event-delivery run metadata to `automation-session-execution`. Tracked in design.md's Open Questions.

## Impact

- **Renderer**: extends the automation editor with a trigger-kind step and event-trigger sub-flow; extends the scheduled-task and run-history list/detail views to render event-sourced runs and backlog-drop summaries.
- **Embedded server** (`apps/server/src/automation`): adds an event-delivery client (poll + IM-message consumption), a local debounce/suppression layer keyed by entity, and extends run claiming to accept event-sourced due work alongside clock-due work.
- **Shared types** (`packages/types/src/automation.ts`): adds `AutomationEventTrigger`, extends `AutomationTriggerSource` with `"event"`, and adds the `event_backlog_dropped` / `rate_limited` error codes.
- **Cross-repo dependency**: this change assumes no server-side event capability exists yet. It depends on the separate `jugglework-server` change `add-github-event-trigger-relay` (GitHub App event capture, `automation_event_subscriptions` routing, JuggleIM headless delivery, the device-facing poll/readiness REST APIs, and — newly — a run-bound GitHub App write-back authorization endpoint and an organization-level posting-rate gate to guard against GitHub's secondary rate limits). This change's P0 tasks that call those APIs cannot complete until that change ships its own P0 scope; both changes should be sequenced together, not assumed independent.
- **Security/privacy**: no new credential storage on the client; the device already excludes connector secrets from automation definitions, and this change adds the untrusted-content prompt boundary for externally sourced event text.
- **Server**: none. Entity-scoped session reuse is a purely local dispatch decision (OpenCode sessions never leave the device); it requires no new server schema, API, or routing behavior. A local entity-close event (already covered by the event types this change subscribes to) is the only signal needed to retire a session's affinity, with a local staleness fallback if that event was never subscribed to — no server involvement either way.

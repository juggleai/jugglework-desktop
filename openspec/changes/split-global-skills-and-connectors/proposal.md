## Why

设置页的「扩展」把工作区技能、全局技能、三个来源的 MCP、组织市场包混排在同一页，用户无法判断某一条属于哪个作用域，也无法预测某个操作会改到哪里。上一轮把「通用」移入全局分组后，「工作区」分组只剩「扩展」这一项，分组本身已失去意义。

同时存在两处使全局条目不可用的缺陷：技能列表在服务端路径丢掉了 `scope` 字段，全局技能因此被当作工作区技能展示；全局 MCP 的移除按钮照常渲染，但服务端只改工作区运行时层，返回 200 却什么都没删，用户点击后毫无反馈。

## What Changes

- 设置页收敛为纯全局配置中心：删除「工作区」分组，「扩展」不再出现在设置导航。
- 全局分组新增「技能」页，只列出全局技能，支持查看详情与删除。
- 全局分组新增「连接器」页，只列出全局 MCP，支持新增、启用/停用、移除，全部直接读写全局 OpenCode 配置。
- 技能列表在服务端路径保留 `scope` 字段，使全局与工作区技能可区分。
- 服务端技能删除接口支持 `scope=global`，可删除全局技能目录下的技能。
- 工作区级技能、MCP 与组织市场包不再进入设置页，继续由会话右侧扩展面板承载。

## Capabilities

### New Capabilities

- `global-extensions`: 全局技能与全局连接器的读取、作用域判定与写入契约。

### Modified Capabilities

- `settings-scope-grouping`: 设置导航去除工作区分组，补充全局技能与全局连接器两页的归属要求。

## Impact

- 设置页分组定义与侧栏渲染，工作区切换器在设置页不再出现。
- 新增全局技能页与全局连接器页两个视图。
- 技能列表映射补齐 `scope`，影响已有的技能作用域徽标与计数。
- Server 技能删除接口新增 scope 参数。
- 新增全局 OpenCode 配置中 `mcp` 段的读写链路。
- 中英文界面文案与相关单元测试。
- 不改变会话右侧扩展面板的行为，不改变组织市场包的安装链路。

## Context

设置页与会话右侧扩展面板承载着两类完全不同的配置。设置页没有工作区上下文的必要性，面板则天然带 `workspaceId`（见 `openspec/project.md`）。此前「扩展」同时出现在两处、且两处展示同一份混合数据，作用域边界因此消失。

技能与 MCP 的作用域在数据层是齐备的：服务端 `listSkills` 为每条标注 `project | global`，`listMcp` 按 `config.global` / `config.remote` / `config.project` 三层合并并标注 `source`。缺的是前端的传递与展示，以及全局层的写入能力。

## Goals / Non-Goals

**Goals:**

- 设置页只承载全局配置，用户不必判断"当前在哪个工作区"。
- 全局技能与全局连接器各自独立成页，操作范围与作用域一致。
- 全局连接器具备完整的增删改能力，写入目标是全局 OpenCode 配置。
- 全局技能可删除。

**Non-Goals:**

- 不在设置页展示或管理工作区级技能、MCP、插件。
- 不改动组织市场包的目录、安装与卸载链路。
- 不为全局层引入新的 MCP 认证或网关机制。
- 不做工作区对全局连接器的覆盖或单独禁用。

## Decisions

**D1：设置页去掉工作区分组，而不是把工作区内容改造成全局。**
工作区技能与 MCP 本身是正确的按工作区隔离，问题只在于它们出现在设置页。会话右侧扩展面板已完整覆盖这三块（连接器、技能、插件/市场），把入口收敛到那里即可。`getWorkspaceSettingsTabs()` 返回空数组后，工作区切换器在设置页自然不再出现——该判定本来就由这个函数驱动。侧栏需要在分组为空时不渲染该分组。

**D2：「扩展」保留路由，只退出导航。**
会话右侧面板通过 `route.tab === "extensions"` 渲染，删除路由会打断该链路。与上一轮「连接器」退出云端导航的处理一致：摘入口，留路由。

**D3：全局技能页的数据来自已有列表，按 `scope` 过滤。**
`listSkills(workspaceRoot, includeGlobal: true)` 已返回两类技能并标注 scope。前置修复是 `extensions-store` 在服务端路径的映射补回 `scope`——该字段在类型上一直存在，只是映射时漏掉，导致所有技能的 scope 在桌面端恒为 undefined。修好后全局页取 `scope === "global"`，工作区面板取 `scope !== "global"`，两处共用一次拉取。

**D4：全局技能删除在服务端按 scope 解析目录。**
`deleteSkill` 增加 scope 参数：`project` 维持现有行为（仅工作区技能目录）；`global` 在全局技能目录集合内解析并删除。路由以查询参数传入。放在服务端而非 Electron IPC，是因为桌面端本地工作区实际走的就是服务端路径，且远程工作区的"全局"指服务端主机的全局目录，只有服务端能正确解析。

**D5：全局连接器直接读写全局 OpenCode 配置文件。**
服务端现有的 `addMcp` / `removeMcp` / `setMcpEnabled` 都只操作按工作区的运行时层，不适合承载全局写入；为它们加 scope 会让"工作区运行时层"这个概念渗进全局路径。改为沿用自定义模型组和自动压缩已确立的做法：用 `readOpencodeConfigFile(workspaceId, "global")` / `writeOpencodeConfigFile(workspaceId, "global", content)` 读写全局配置文件的 `mcp` 段，JSONC 编辑保留注释。写入后标记引擎需要重载。

**D6：列表展示复用合并结果，写入走全局文件。**
连接器页的条目与连接状态取自已有的 MCP 列表（按 `source === "config.global"` 过滤），因为只有它带引擎侧的连接状态；增删改则写全局文件。读写不同源是有意的：状态是运行时事实，配置是文件事实。

**D7：全局连接器不提供工作区专属操作。**
工作区运行时层的启用/停用语义（`disabled_providers` 式的按工作区覆盖）不适用于全局条目。全局连接器的启用/停用直接改全局配置里的 `enabled` 字段，对所有工作区一致生效。

## Risks / Trade-offs

- 用户要管理工作区扩展必须进会话页。这是入口收敛的代价，换来的是设置页里不再有"这一条到底改哪儿"的疑问。
- 全局连接器的改动立即影响所有工作区，没有单工作区回退。这是全局作用域的定义，页面标题与说明需明确表达。
- 修复 `scope` 传递后，此前被误标为「工作区」的全局技能会在会话面板中消失（移到设置页）。这是纠正而非回归，但对已习惯旧位置的用户是可感知的变化。
- 连接器页读列表、写文件两条链路，存在文件已改而列表未刷新的窗口；写入后主动刷新 MCP 列表来收敛。

## Migration Plan

1. 先发服务端技能删除的 scope 参数，旧客户端不传即维持原行为。
2. 前端修复 `scope` 映射，两处消费方（全局页、会话面板）同时按新语义过滤。
3. 导航调整与新页面为纯前端变更，无数据迁移。
4. 不改写用户既有的全局或工作区配置文件，只在用户主动操作时写入。

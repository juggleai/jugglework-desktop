# Word 与 AFFiNE 原生操作适配矩阵

本文是 Desktop 的 SDK 适配契约和可行性验收门槛。单普通段落结果见 [M3-A](milestone-3a.md)，固定多段及基础 marks 结果见 [M3-B](milestone-3b.md)，普通段落拆并和受限原生并发见 [M3-C](milestone-3c.md)；完整支持集合与 W-01～W-16 尚未通过。Docs 的桥消息以[原生编辑桥契约](../../../../jugglework-docs/openspec/changes/add-jugglework-docs-adaptation/editor-bridge.md)为准。适配使用 AFFiNE 原生对象和事务，不引入第三种正文模型。

## 已有事实与待证明事实

现有 OfficeDocuments 支持当前 SDK 模型、人工／AI 内容工具、保存和重新打开。公开宿主代码尚未证明可取得覆盖人工与 AI 的完整操作流，也未证明它与 BlockSuite 稳定对象及原生相对位置的双向映射。现有本地 AI 可编辑 Word，不代表完整跨编辑器适配已经存在。固定 SDK 的人工／AI 事件和单段定点往返已验证；完整操作流、原生相对位置并发映射及恢复仍待证明。

PoC 使用真实 SDK、真实 AFFiNE 服务和两个独立原生客户端，不能用 mock 事件或静态 DOCX 转 HTML 代替。每项记录 SDK 事件／接口、原生命令、目标定位、回写、保存重开和未修改对象结果，再更新状态。

首次关联、共同检查点及恢复握手以 [word-recovery.md](word-recovery.md) 为准；原生出站批处理及输入延迟以 [collaboration-performance.md](../../../../jugglework-docs/openspec/changes/add-jugglework-docs-adaptation/collaboration-performance.md) 为准。两者不改变 AFFiNE 原生同步协议。

## 能力矩阵

| 类别 | Word → 原生编辑事务 | 原生变化 → Word | 必须验证 | 当前状态 |
| --- | --- | --- | --- | --- |
| 段落与文本 | 人工／AI 插入、删除、替换映射到原生文本目标 | 定点更新同一 SDK 段落及文本范围 | 中文、emoji、UTF-16、连续输入、段落拆并、非目标文本 | 固定多段顺序插删、普通段落拆并、既有加粗／斜体随拆并保持和受限原生并发文本已有源码回归；带格式拆并真实 SDK、未转发窗口、结构并发及完整集合待验证 |
| 标题与列表 | 对应 BlockSuite heading／list 结构与属性 | SDK 标题级别、列表结构与编号 | 嵌套层级、删段落后稳定映射、重开 | 既有 h1／h2、两种单级列表的文本及类型保持通过；类型改变、嵌套和其余标题级别待验证 |
| 基础字符样式 | 原生 marks | SDK 范围样式 | 加粗、斜体、链接，未修改范围保持 | 加粗／斜体设置清除及保存重开通过；链接及其他格式待验证 |
| 基础表格 | 原生 table／row／cell 事务 | SDK 表格与单元格操作 | 新增／删除行列、中文单元格、对象定位 | 待 PoC |
| 内嵌图片 | 目标页原生附件身份和 image 节点 | SDK 图片对象及资源 | 图片字节、尺寸、无跨租户私有 URL | 待 PoC |
| 评论锚点 | 原生稳定目标周围的事务 | Word 内容回写不能破坏云端锚点 | 评论前后插入删除、编辑历史及定位 | 待 PoC，不承诺 Word 批注双向 |
| 复杂对象 | 尚无已验证映射 | 保持原内容并暂停 | 浮动形状、复杂公式、页眉页脚、修订、嵌入对象 | 不开放，待单独验证 |
| AFFiNE 特有块 | 仅已验证可表示的块可进入 Word | 未验证时保持云端并暂停 | 图示、折叠块、同步块和其他 Word 无直接对应对象 | 不开放，待单独验证 |

首个支持集合必须覆盖文本、标题、列表、基础表格与内嵌图片；部分成功不能把整个集合写成通过。复杂 Word 完全保真不是已有事实，不能在界面使用“无损同步”。

## 操作约束

1. 捕获点覆盖真实人工输入与 AI 共同模型；只捕获 Agent 工具调用不足以通过。
2. 目标使用原生稳定对象／相对位置与 SDK 对象关联，不能把历史绝对字符偏移直接当当前目标。
3. 更新提交到同一 AFFiNE 编辑事务，保留原生 Y.Doc；不能整页 setContent、覆盖 ydoc 字节、轮询 HTML 或互换 DOCX 文件。
4. 云端回写进入当前活跃 SDK 模型后才保存；不得先覆盖磁盘再等待旧模型关闭。
5. 来源标记仅抑制本次远端回写导致的重复事件，真实后续人工输入必须仍能发出。
6. 人工与 AI／远端操作并发时，AFFiNE 负责合并；适配器只做对象定位及格式转换。若必须另写正文合并算法才能工作，则判当前方向未通过。
7. AI 选区证明、页面提交、模型代次、保存和外部接管规则继续适用；云端事件不得刷新陈旧引用或绕过未知结果保护。
8. 绑定只属于一个 sourceServerOrigin＋sourceUserId＋tenantId＋pageId，切换组织不自动复制或改变关联。

## 验收场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| W-01 | 本地人工编辑 → 云端 | 两个原生客户端看到同一修改；刷新及服务重启后存在 |
| W-02 | 本地 AI 编辑 → 云端 | 仍使用原聊天与 Office 工具；云端出现对应原生事务且不重复 |
| W-03 | 云端成员编辑 → 本地 | 同一 SDK 模型显示修改，原路径保存重开后存在 |
| W-04 | 人工／AI 与另一成员同时编辑 | 按原生协作收敛，非目标内容与评论锚点符合样例，无整页覆盖 |
| W-05 | 回写事件再次由 SDK 发出 | 不形成无限回环；后续真实本地编辑仍可发送 |
| W-06 | IME 或 AI admission 中收到远端变化 | 不覆盖未提交文字，不跨模型回写，不破坏既有选区证明 |
| W-07 | 断网与恢复 | 原生恢复接续，不产生自研桥离线日志或失权重放 |
| W-08 | 文件关闭重开及模型重建 | 核验共同检查点、文件摘要及稳定映射；无检查点／本地独立变化时暂停；不依赖旧 engineFileId |
| W-09 | 权限降为 reader／成员退出 | 暂停可写联动，旧连接和缓存不能继续写；本地文件仍保留 |
| W-10 | 同一文件跨 Personal／A／B | 不能自动重绑或把一侧修改发送给其他租户 |
| W-11 | 不支持对象或 schema 不匹配 | 自动适配暂停，双方内容保留且原因可见 |
| W-12 | 写入或保存响应丢失 | 显示结果待确认，不自动重发和重复套用 |
| W-13 | 另存为／外部重命名 | 副本默认无自动绑定，移动文件需明确重新定位 |
| W-14 | Desktop 关闭后云端编辑 | 文件未变时经原生检查点恢复云端变化并定点回写；本地也变则暂停保留双方；不声称关机期间本地实时更新 |
| W-15 | 100ms 批次与授权 | 输入即时，原生合并发送；连续输入不无限推迟，同批／下一批授权及重连遵守失权规则 |
| W-16 | 检查点写入与关闭故障 | 资源／关联指针写入中退出不产生半个生效检查点；Word 已保存和服务端已落库分开显示 |

## 发布门槛

先完成 W-01～W-06 证明“可原生操作适配”，再完成其余恢复与权限场景。输出真实 SDK API／事件证据、AFFiNE 原生命令映射、平台／版本、样例和持久化结果。若 SDK 只有完整文件读写能力或缺少稳定回写，则 Word 双向需求为技术阻塞，不能将导入／导出、截图变化或 XML 可解析当作通过。

面向云文档统一使用 AFFiNE 编辑器可以作为单独产品调整，但未经明确变更不得删除本地 Word 双向要求或把它标为完成。

# M4-E：DOCX 原件接入

Word 顶栏 page 模式已形成以下源码闭环：先完成现有 Office 保存，读取当前存活 SDK 基础对象，使用该 Word 所属工作区客户端预检文件大小并下载同一路径的真实 DOCX，不能使用组织控制面客户端代替本地文件客户端。在 Desk 计算 SHA-256 并与本次保存摘要一致后，把原件和基础对象交给当前组织后台隐藏的 product 视图。上传保持当前 Word 页面，完成后释放临时 product 视图；只有用户点击“打开云端”才跳转。

product 视图以同一 requestId 执行 Docs multipart preview、commit 和 status。原件限制 10MiB，保存到 AFFiNE 原生 Blob；响应未知时只查询稳定任务，不创建第二个 requestId。commit 完成后继续使用原有 editor 一次性交接、逐对象映射、持久绑定和首个共同检查点，全部成功后才显示已建立双向同步。

上传对象限定 `id/text/kind/marks`，SDK 的 `start` 等本地定位字段不进入云端严格协议。明确的 4xx 拒绝保留原始原因；响应未知时 status 查询失败也不能覆盖最初错误。上传失败在 Word 顶栏保留可查看的错误提示，重试时清除。

Office 主世界桥通过函数源码注入；安装与调用脚本必须自包含，不能引用主进程模块闭包变量。对应回归在独立 JavaScript 上下文执行正式注入脚本。

首次 Word 正文通过原生页面骨架和 Yjs 基础块初始化，逐项保留空段落、尾随空格、字面 Markdown 字符及基础样式。保存回执 `/office/saved` 必须携带精确模型身份、`savedAt` 与 `savedFileSha256`；缺少真实保存证明不推进共同检查点。

受管普通文档页头在当前成员仍有结果页面 Doc.Read 时显示原始 DOCX 文件名和下载入口。首次后台 editor 交接以原件 SHA-256 的带填充 Base64URL 编码作为原生 Blob sourceId，幂等写入一个 `affine:attachment`；文件保存校验继续使用十六进制 checksum。Word 映射只绑定 paragraph／list 对象，受管附件不参与 Word 投影。附件写入或元数据核对不能确认时不建立关联。

宿主请求缓存不保存正文、DOCX 字节或长期令牌；请求复用同时核对来源服务器、账号、组织和文件摘要。源文件路径和登录令牌不进入 Docs product 页面。原件接入目标固定当前已进入的组织 Workspace。

Word 顶栏使用灰色云朵箭头图标表达双向同步：开启时显示上下双箭头，未开启或暂停时显示单个向上箭头，上传／连接期间显示进行中状态。保存按钮和云端图标旁不显示“已保存”“双向同步中·打开云端”等常驻文字；保存结果、同步状态和点击动作放入系统悬浮提示及无障碍标签，避免原生编辑视图遮挡提示。已关联文件不再显示重复上传入口。工作区和独立窗口复用同一图标；独立窗口读取所属真实 Word 的关联状态，已关联时经主窗口当前身份打开对应云页面，未开启时回所属工作区上传或恢复，不能从文件窗口取得源凭据或任意文档控制能力。双向同步验收步骤与限制见 [design.md](design.md#6-文件上传与首次转换)。

page 模式目标固定当前已进入的组织 Workspace，不提供 Folder／Collection 目标选择。移动文件按当前账号、组织、本地工作区和共同检查点 SHA-256 查找唯一候选，用户确认后才重新定位；重名、同摘要多候选和文件变化均不自动绑定。Office 模型关闭后保留共同检查点并立即释放后台 AFFiNE editor。

产品入口固定 page 模式，不提供独立 attachment-only 模式。尚未完成：图片／表格／复杂列表转换、完整对象恢复，以及真实 Electron＋远端 Provider 上传／移动／重开联合矩阵。

本机开发版真实验收：测试 Word 的 12 个基础段落（含末尾空段落）完成原件上传、云端页面创建、原生对象映射及首个共同检查点；持久关联为 active，顶栏显示“双向同步中 · 打开云端”，保留原 Word 页面。该结果不替代双向内容编辑及跨重启恢复矩阵验收。

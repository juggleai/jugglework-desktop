## Why

设置中新增的自定义模型组此前写入当前工作区配置，导致用户切换工作区后看不到已添加的模型组；同一台 Mac 同时运行生产版与 dev 版时，配置目录边界也不够明确。另一方面，本地类型模型组缺少稳定的详情与编辑入口，断开连接时条目会暂时从列表消失，使用户误以为配置已被删除。

## What Changes

- 用户新增的自定义模型组写入当前运行环境的全局 OpenCode 配置，并在该运行环境的所有工作区中生效。
- 生产版与 dev 版继续使用各自的 `OPENCODE_CONFIG_DIR`，全局配置不跨运行环境混用。
- 保存已有工作区级自定义模型组时，将同 ID 配置迁移到全局配置并清理旧副本。
- 本地模型组显示「本地」标签，支持查看详情和进入编辑；编辑时模型组 ID 不可修改，API Key 留空表示保留原值。
- 断开连接后条目仍保留在主列表，仅状态变为「已断开」；重新连接成功后原地恢复为「已连接」。
- 操作区按「查看详情」「重新连接」「彻底删除」排列，使重新连接紧邻彻底删除。

## Capabilities

### New Capabilities

- `local-model-groups`: 本地自定义模型组的全局配置作用域、迁移、详情编辑和连接状态展示契约。

### Modified Capabilities

无。

## Impact

- 设置页模型组列表、详情弹窗和连接状态管理。
- App 与 Server 的 OpenCode 配置读写路径。
- 自定义 provider 配置写入、迁移及删除逻辑。
- 中英文界面文案与相关单元测试。
- 不新增依赖，不迁移生产版与 dev 版之间的配置。

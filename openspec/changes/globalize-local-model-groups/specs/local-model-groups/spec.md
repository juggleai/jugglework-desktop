## ADDED Requirements

### Requirement: 自定义模型组在当前运行环境内全局生效
系统 SHALL 将用户新增或编辑的自定义模型组写入当前运行环境的全局 OpenCode 配置，使其在该运行环境的所有工作区中可见和可用。全局作用域 MUST 以 `OPENCODE_CONFIG_DIR` 为边界，生产版与 dev 版使用不同配置目录时 MUST NOT 相互覆盖。

#### Scenario: 切换工作区
- **WHEN** 用户在工作区 A 新增一个自定义模型组后切换到工作区 B
- **THEN** 工作区 B 的设置页仍显示该模型组，并可使用相同模型配置

#### Scenario: 同时运行生产版与 dev 版
- **WHEN** 生产版与 dev 版分别设置不同的 `OPENCODE_CONFIG_DIR`
- **THEN** 两个运行环境分别读写各自的全局模型组配置，不因同时运行而互相覆盖

### Requirement: 旧工作区模型组可安全迁移
系统 SHALL 在保存旧工作区级自定义模型组时先写入同 ID 的全局配置，并仅在全局写入成功后清理工作区旧副本。彻底删除自定义模型组时 SHALL 同时清理全局配置和当前工作区可能遗留的同 ID 副本。

#### Scenario: 编辑旧工作区模型组
- **WHEN** 用户编辑并保存一个只存在于工作区配置中的自定义模型组
- **THEN** 最新配置出现在全局配置中，工作区同 ID 旧副本被移除

#### Scenario: 全局写入失败
- **WHEN** 保存时全局配置写入失败
- **THEN** 系统报告失败且不删除原工作区配置

### Requirement: 本地模型组支持详情与编辑
设置页 SHALL 为用户配置的模型组显示「本地」标签。用户点击该条目或「查看详情」时 SHALL 打开详情弹窗，并可从详情进入编辑态。编辑已有模型组时 provider ID MUST 保持不可修改；API Key 输入留空时 MUST 保留原有凭据。

#### Scenario: 查看本地模型组
- **WHEN** 用户点击带「本地」标签的模型组
- **THEN** 系统展示其名称、provider ID、Base URL、模型和认证配置详情

#### Scenario: 编辑时不填写 API Key
- **WHEN** 用户编辑其他字段、保持 API Key 为空并保存
- **THEN** 其他字段按输入更新，原 API Key 保持不变

### Requirement: 断开连接不移除模型组条目
断开、重新连接和连接成功后的模型组 SHALL 始终保留在同一个主列表位置，仅连接状态和可用操作发生变化。断开时 SHALL 显示「已断开」和重新连接入口；连接成功时 SHALL 原地恢复为「已连接」。操作区中的「重新连接」MUST 紧邻「彻底删除」。

#### Scenario: 断开模型组
- **WHEN** 用户断开一个已连接的本地模型组
- **THEN** 该条目仍在主列表中，状态变为「已断开」，并显示重新连接和彻底删除操作

#### Scenario: 重新连接模型组
- **WHEN** 用户对已断开的模型组发起重新连接
- **THEN** 连接过程中条目不消失，成功后同一条目状态变为「已连接」

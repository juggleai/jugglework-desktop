## Context

详细方案位于 [office-document-editing-design.md](../../../docs/office-document-editing-design.md)。项目使用 Server 托管运行时，Electron 提供原生能力，React 展示聊天及文件面板。现有批量 `artifacts/resolve` 已能确认工作区真实文件及大小，第一批实现复用该接口，不重建文件解析服务。

## Goals / Non-Goals

目标为可恢复的轮次交付、统一文件入口和操作、独立窗口及本地 Office 编辑。交付分批完成，任务清单按实际验证结果勾选。首批完成聊天到文件操作的闭环；Office 编辑独立于卡片功能开关。

分享、上传云端和远程 Office 编辑不在首版范围。

## Decisions

- 聊天按真实用户请求边界归集文件，在总结后仅渲染一次。已有解析结果与本轮候选相交，不将整个会话文件套入历史轮次。
- 文件名、大小写及原生路径保真。只有确认存在的文件可打开；同名歧义不转换，失败工具不产生交付。
- Markdown 在 token 层处理已确认文件引用，正文与卡片共用打开动作，不改消息存储文本。正文文件与普通网址均只显示链接色文字，不带下划线、背景、边框、图标或下拉按钮；产物卡片保留类型图标。卡片与两种编辑顶栏的云端分享仅展示禁用图标，TODO 只记录在任务文档中。
- 通用文件操作由会话级上下文提供，持有正确工作区及聊天身份；附件进入既有输入框草稿，不自动发送。文件副本经原生对话框复制，支持空文件及大型文件，不经 base64 搬运整个文件。
- 聊天右侧栏有草稿时，附件、独立预览、默认应用打开及另存为先保存或取消；复用文件面板现有草稿及保存接口。
- CSV 与 Word 共用 OfficeEditor 及原生 Office 宿主，按格式打开 SDK 的 doc/sheet 页面，保存、关闭、自动保存与外部交接沿用同一服务；CSV 不进入 React 轻量表格及文本草稿写回路径，保存仍为 UTF-8 CSV，并要求单个工作表。TSV 保留轻量表格编辑和共享文本草稿。
- Electron preload 通过异步能力检查确认实际主进程已注册文件窗口。旧主进程或旧 preload 下禁用独立入口并提示重启，避免 Vite 更新后仍调用不存在的 IPC；不自动重启正在运行任务的桌面应用。
- 文件浏览器与聊天右侧栏共同使用 FileViewer 和同一本地 Server。TSV、Markdown 与文本通过 Electron 共享草稿、统一保存及关闭确认；DOCX、CSV、XLSX、PPTX 两处显示同一内容，显式激活时交接同一存活 WebContentsView，非活动宿主显示当前快照。
- 原生文件窗口、页面标题及任务栏/Dock 名称统一为“JuggleWork 文件浏览器”，文件名在内部标签展示；macOS 辅助包为 `JuggleWork File Browser.app`，不复用测试宿主名称。
- 生成文件、交付完成及恢复历史只更新产物，不自动打开面板。点击正文引用、卡片主体或产物列表文件时，复用右侧既有“文件”面板的路径 tab；卡片右侧“在独立窗口打开”图标单独触发窗口动作。
- 指定文档 Logo 用于窗口和任务栏。Windows 使用文档独立 AppUserModelID 与 ICO；macOS 使用轻量 AppKit Dock 入口及 ICNS，通过管道激活主进程持有的文件窗口，保持同一 Office 页面与模型。Dock 入口不承载编辑器，系统窗口归属仍在主进程。取消退出或保存失败时保留窗口和入口，清理窗口后才停止 Runtime。
- 完整产物索引采用工作区 JSON manifest 与唯一 Server 写入方；不新增数据库或复杂锁。初期消息候选校验路径作为旧消息兼容，不视为已完成受控生成与历史快照能力。
- 会话交付通过 `sessions/:sessionId/file-deliveries` 批量查询，存在 collecting/finalizing 记录时轮询；运行结束由 Server 生命周期确认，重启恢复先核实引擎空闲。普通工具、受控生成和媒体请求分别绑定来源，不按当前焦点补填。
- `jugglework_artifact_generate` 承载 `artifact.generate_files`，复用工具上下文的 Bash 权限及取消信号，直接传递可执行程序和参数；专用输出目录自动枚举，失败残留不交付。local-queue、local-steer、remote-pending 在 admission 前按既有确定性映射绑定真实引擎用户消息 ID，使用稳定的 admission 批次标识，不额外创建宿主 run；受控生成与 Office、媒体工具按实际 parentID 归属。只有实际 assistant 完成、工具结束且引擎空闲时才最终确认，排队回执不能提前结束；重启重试沿用同一记录，旧会话没有绑定时保留兼容路径。
- Office 原生内容查询/修改通过现有语义工具按需发现并由宿主调用 HTTP MCP；不向 OpenCode 注册完整原生目录；创建、打开、保存、关闭和导出由宿主控制。最终交付必须等待保存成功，不能依赖模型主动保存或自动保存定时器。
- 包装层统一使用 Office 包名、文件名、导出接口、配置与日志名称；本地导入同步执行命名适配，原生内核、固定页面协议及许可原文保持兼容。
- SDK 仅从显式本地资源启动，默认不依赖外部应用；格式、平台、离线能力与分发范围分别验收。
- 本地供应资源包含 darwin-arm64、darwin-x64、win32-x64 的 0.0.0.499 原生内核，共用项目内适配包 office-docs-ai-engine 0.2.196-office.1，完整平台目录通过 Git LFS 和独立版本/哈希清单纳入项目。Intel 的 Rosetta 四格式保存重开及三个平台实际资源复制验证已通过；Windows 运行、Intel 实机和完整签名安装包仍单独验收，不据此开放跨窗口迁移。
- 内置 Server 的生产依赖必须同时声明于桌面打包入口，包含 XML/ZIP 处理库；依赖归属回归保证配套版本一致。构建先暂存 Server，再使用 Electron 内置 Node 导入 embedded.js，不能以源码 Server 可运行推定安装包依赖完整。
- SDK 0.0.0.499 的 XLSX 公式导出由 OfficeEngine.save 统一适配：通过固定版本 jszip 和 XML 解析器移除工作表 f 节点的界面前导等号，保留数组/共享公式属性、缓存和其他部件，同目录原子替换后才确认保存；不重建工作簿，不扩展 Agent 原生保存权限。
- 原生进程启动前向系统申请空闲端口，wrapper 确认最终实际端口；避免快速重启连续绑定默认端口附近的端口失败。预览 URL、保存请求和 MCP 连接仍由实际启动结果派生，不固定为默认端口。
- DOCX、CSV、XLSX、PPTX 页面由 Electron WebContentsView 承载，隐藏和切换标签保留模型。原生页面的保存请求和快捷键统一转到 Server 保存接口；禁止 SDK 原生另存路径及生命周期操作绕过宿主。
- 本地资源包含 wrapper、配套脚本、完整平台目录和版本/哈希清单，通过 `scripts/import-office-engine.mjs` 导入。使用环境变量 `JUGGLEWORK_OFFICE_ENGINE_DIR` 指定目录；缺失时保持普通文件功能可用。
- 已打开的 DOCX、CSV、XLSX、PPTX 通过现有语义工具提供 `office.current_document` 和 `office.save_document`，身份取实际工具调用的聊天；每轮系统提示重新查询实际模型，格式对应 doc、sheet、slide 内容工具；手动新建 Word 由文件浏览器调用宿主 API；不提供 Agent 新建语义动作。
- 文件窗口页面准备及原生页重挂成功后才提交归属。重挂失败恢复原宿主及可见性，不关闭重开模型。交接前通过 Server 查询所属聊天运行、当前文档交付及保存状态，等待期间由原宿主显示可取消原生提示；取消或宿主关闭不提交迁移。卡片、更多菜单、已有窗口和内容区接续共用宿主流程，首次打开没有现有页面时不执行迁移等待。
- macOS ARM64 隔离宿主已验证 Word 选区和用户/MCP 编辑的撤销重做在迁移后保留。AI 按版本撤销须先查询实际编辑记录；界面撤销重做已经覆盖的原始 revision 可能被 SDK 拒绝，保持错误，不猜测其他版本或改用删除文本模拟撤销。真实中文输入按格式验收；原生编辑区组合期间阻止文档保存、关闭和打开快捷键，不执行宿主动作，也不放行 SDK 自身的文档快捷键。
- 引擎意外退出替换故障会话状态，旧就绪查询及保存响应不得覆盖故障或确认交付。宿主恢复接口 `POST /workspace/:id/office/:documentId/recover` 仅用于故障文档；原生确认丢弃未保存内容后，从原路径重新导入，保留文档及标签身份，双宿主同步状态。运行中拒绝恢复，取消不改变状态；恢复不提供 Agent 动作。

- 文件接口拒绝重命名、覆盖或删除存活 Office 模型的源、目标及父目录，先由用户保存关闭；关闭、外部接管、导出准备及故障恢复复用实际活动与交付检查，未知状态不视为空闲。
- 原生页面崩溃或加载失败上报单文档故障并同步两种宿主，恢复前清理原页面协议处理器；Cmd/Ctrl+O 根据当前宿主复用右侧或独立文件标签，不提供旧的返回主窗口动作。

## Risks / Trade-offs

- 无结构化路径的普通 Shell 输出无法可靠判定 → 受控生成契约提供专用输出目录，宿主自动登记；该能力完成前不宣称所有静默生成均可发现。
- 初期消息推导没有原始交付快照 → 未记录的历史任务只展示当前可确认的文件，不虚构历史大小。
- 内核页面和跨窗口迁移兼容性未全部验证 → 按格式、平台分别控制能力，禁止销毁模型后假装无损迁移。
- Windows 和 Intel SDK 资源尚不齐全 → 保留资源任务和未开放状态，不自动下载或替换平台二进制。

## Migration Plan

1. 先上线兼容既有服务端的整轮卡片及文件操作；既有文件面板默认入口不变。
2. 增量增加 manifest、受控生成及最终交付确认；旧历史消息保留有限兼容。
3. 本地聊天右侧栏首先开放经过验证的 Word 基础编辑；文件浏览器与侧栏编辑一致性、共享草稿及 Office 保持状态交接分别验收。
4. 回退 Office 时保留 dirty 文档保存退出能力，不回退为破坏多工作表的旧编辑路径。

## Format adapters and verification

- XLSX 使用完整原生工作簿模型，CSV 的单表保存限制仅作用于 CSV；两张表及跨表公式经真实 SDK 保存重开验证。PPTX 使用 slide 页面和模型，以 `slide_get_info.is_open=true` 判定就绪，不能把导入中的成功响应视为 ready。
- 历史产物 tab 同样进入原生 Office 宿主；旧二进制表格的单表重建保存已移除，旧格式及远程表格仅提供多表只读预览。

- 当前文档上下文不含预览 URL；选区按原生格式解析，排除页面模型 ID 和提示词。每次上下文查询通过已有本地桌面桥，按 workspaceId、documentId、pageId 读取所属可见存活页面的真实状态；读取前后核对页面及聊天当前模型。未知、超时、隐藏、切换或恢复返回 null，不缓存通知坐标，不依赖全局焦点，不启用 SDK 内部 AI 浮层；移除原通知 preload 和 IPC。Word 采集连续字符范围，表格采集当前真实子表的行列范围并按模型网格限制整行/整列末端，PPT 采集页面及形状身份；跨单元格、浮动对象、PPT 备注、框选及组内选择暂不支持，普通单个文本形状在内部编辑时额外提供 textSelection（shapeId、start、count、可选 selectedText），按 UTF-16 和段落分隔符计算，支持反向和折叠选区；非法坐标返回 null。只有该字段代表内部文字范围，PPT 形状身份不能代替文字范围。范围格式修改使用 slide_set_text_property；整框文字替换不能承诺保留其他字符样式。

- Office 工具通过 office.tools 返回当前格式名称或单个原始参数定义，通过 office.call 执行并登记调用聊天的修改；创建、保存及其他生命周期操作不进入该目录。多工作区匹配优先使用本轮实际工作目录，避免非 Git 仓库根目录 / 覆盖实际目录。
- macOS ARM64 原生 CSV 删除首行的可见回显、独立窗口迁移和已保存状态已验收；真实模型对话通过按需查询 schema、同模型删除和原路径保存，磁盘保留两条数据。实时选区的真实模型对话已验证：独立文件浏览器选中 CSV A2，所属聊天仅按“选中单元格”指令修改，模型查询选区、编辑同一原生模型、保存及回读完成；原生页面和磁盘内容一致，其他单元格保留。
- 基础选区的 macOS ARM64 桌面验收还覆盖 Word 六个标题字符在存活页面迁移后保持真实范围、右侧聊天按选区替换标题且正文保留，以及 XLSX 从首表切换到第二工作表后选择 A1:B2 返回新 sheetId 和范围。侧栏隐藏后选区为 null；窗口无需获得全局焦点。复杂选区与其他平台列于 4.20，普通文本形状内部文字选区已适配，其余复杂选区仍待验收。

- macOS ARM64 开发宿主的真实模型对话已验证同一聊天切换 DOCX、XLSX、PPTX 后使用当前格式模型：Word 指定文本替换保留正文，Excel 跨表 SUM 公式保留并更新至 60，PPT 指定页面替换且其他页面与页数不变；三轮文件交付、原路径保存和磁盘内容一致。

- DOCX、CSV、XLSX、PPTX 统一保存通过已有桌面桥确认当前 workspaceId、documentId、pageId；Word 等待输入合并及原生确认，表格等待组合输入结束并显式提交当前单元格，提交成功后才退出编辑，跳过 SDK 未被等待的重复提交。PPT 等待自身文字组合结束、将文字缓冲提交模型并等待原生提交队列；SDK 队列吞掉异常，宿主另行检查 HTTP 提交结果，任一失败在当前页面存活期间持续阻止保存，恢复后使用新页面状态。PPT 还在页面捕获阶段及宿主快捷键入口检查编辑器真实组合状态，避免 SDK 自行保存并失焦。未知状态、提交失败、超时或页面失效均拒绝继续写盘并保留输入。模型 dirty 不能代替页面就绪。macOS ARM64 侧栏与独立窗口的四种格式中文上屏后立即保存通过，表格非目标内容、工作表及 PPT 第二页保留；PPT 组合期间三个文档快捷键及页面迁移通过。
- macOS ARM64 本地排队的 PPT 只读任务在前一轮保存交付后执行，该轮 ready 且文件目标和交付项为空。

- XLSX 在创建原生模型前按 OOXML 内容类型检查透视表及缓存；已确认 SDK 导入损失的文件返回 office_readonly_required，清除旧聊天编辑目标，两种宿主共用原始文件只读多表预览。保存及故障恢复复查，不能恢复旧透视部件来掩盖内存模型损坏。默认应用及原件副本保持可用，解析失败不视为可编辑。
- 限定 PPT 样例的动画目标、时长、切换、主题颜色/字体、母版及图片关系保存后保留，但 bldLst 和部分 cTn ID 被省略；仅通过部分结构核对，Office/WPS 实际播放及往返未验证。
- macOS ARM64 真实模型对话已按 PPT textSelection 的 start=2、count=2 仅将“发布”设为红色加粗，页面、保存回读及 OOXML 一致，其他文字和第二页保留。透视表只读预览在两种宿主保留原件第三张表的 11、33、44，保存禁用、当前 AI 文档为空且原件 SHA-256 不变。
- 首次创建 Office 页面依赖实际平台 SDK 资源；已有页面跨窗口迁移仅开放 macOS ARM64。其他平台在保存、等待和重挂前拒绝迁移并提示先保存关闭后重开，所有入口共用此边界；模拟平台回归不替代 Windows 或 Intel 实机验收。
- macOS ARM64 在 Electron 44 内置 Node、无系统工具 PATH、只允许回环网络的进程沙盒中，已验证真实 SDK 四种格式的编辑、保存与重开，以及资源缺失降级；独立磁盘读取保留非目标内容。该结果不覆盖签名安装包或完整页面的字体/worker/剪贴板，不声明远程 AI 离线可用。
- SDK 本体不再整体忽略：原生文件走 Git LFS，wrapper 与清单走普通 Git，仅排除运行日志与临时输出。afterPack 按目标复制到 ASAR 外，macOS 用 builder 解析后的身份先签 SDK、更新哈希再封存主应用；缺失平台或仅 LFS 指针则打包失败。
- 桌面向 embedded Server 显式传入自身资源目录，安装后固定为 Resources/office-engine，不读取外部 App 或通过环境覆盖该路径；原生工作目录与日志使用用户数据区，安装资源只读。实际复制签名后的 ARM64 SDK 已通过隔离引擎验收，不替代完整应用签名、公证和安装验收。

## ADDED Requirements

### Requirement: Agent 多格式编辑上下文
系统 SHALL 在每轮模型调用时按调用聊天提供当前 Office 文档的路径、类型、就绪状态、真实模型 ID 及当前选区；不使用全局窗口焦点。DOCX SHALL 使用 doc 内容工具，CSV、XLSX SHALL 使用 sheet 内容工具，PPTX SHALL 使用 slide 内容工具。未就绪或上下文查询失败 MUST 明确报告，不得沿用历史模型或选区。Agent 保存 SHALL 使用宿主保存动作，不提供 Agent 新建文档动作。

#### Scenario: 本轮聊天身份与插件初始化不同
- **WHEN** 系统提示转换接收到本轮 sessionID，插件初始化包含其他聊天身份
- **THEN** 使用本轮聊天及工作区查询文档，每轮重新读取状态，其他聊天的模型与选区不进入提示

#### Scenario: 编辑当前 CSV 第一行
- **WHEN** 用户要求删除已打开 CSV 的第一行
- **THEN** Agent 读取实际工作表身份，用 sheet 内容工具删除索引 0 的一行，页面更新同一模型，由宿主保存原 CSV；若明确保留表头并删除第一条数据，则删除索引 1

#### Scenario: 原生页面选区与模型失效
- **WHEN** Agent 查询当前文档及选区
- **THEN** 宿主按 workspaceId、documentId、pageId 从所属可见存活页面即时读取，页面数据不能替换宿主模型身份；读取期间隐藏、切换或模型失效后不返回旧选区，通道失败或格式未知返回 null，不沿用历史通知

#### Scenario: 普通单元格选中后从聊天编辑
- **WHEN** 用户在 CSV 或 XLSX 页面选中单元格，在所属聊天要求 AI 修改选中内容
- **THEN** 无需 SDK 内部 AI 浮层，当前文档查询返回真实子表和最新行列范围，内容工具使用该模型与范围修改，统一宿主保存后才确认完成

#### Scenario: 暂不支持的复杂选区
- **WHEN** Word 跨单元格选择、表格浮动对象选择，或 PPT 备注、框选区域与组内选择无法提供已适配坐标
- **THEN** 返回 null 并要求明确范围，不回退到旧单元格或用外包字符范围猜测；PPT 页面和形状选区不代表形状内部文字范围

#### Scenario: PPT 单个文本形状内选择文字
- **WHEN** 用户在普通单个 PPT 文本形状内选择文字或放置光标
- **THEN** 当前文档查询额外返回该形状的 textSelection，以 UTF-16 码元和段落分隔符计算 start/count，支持反向和折叠范围；格式修改先读取原文和工具定义，再按该范围设置字符格式，不用整框替换冒充保留其他字符样式的局部编辑；非法坐标返回 null

### Requirement: 本地引擎及格式能力
Server SHALL 管理唯一的本地 Office 引擎，按实际平台和配套版本读取本地资源，不自动下载。系统 MUST 分别验收 Word、Excel、PPT 与各平台，资源缺失时保留通用文件操作。

#### Scenario: SDK 资源缺失
- **WHEN** 当前平台缺少可用 SDK
- **THEN** 内置编辑不开放，卡片、文件信息和默认应用打开仍可使用

#### Scenario: 建立文档会话前失败
- **WHEN** Office 引擎版本未适配、能力查询失败、桌面桥缺失或打开文档请求失败
- **THEN** 右侧编辑面板结束载入，内容区显示具体原因，顶栏不重复显示“文档打开失败”；独立窗口的编辑内容区同样结束载入并显示原因；未建立会话时保存保持禁用，不挂载原生页面。能力查询尚未完成时仍显示载入状态

#### Scenario: 本地引擎不依赖系统 Node 或 SDK 下载
- **WHEN** 宿主使用 Electron 内置运行时，PATH 中没有 Node/npm/npx/Bun，外网不可用但本机回环可用
- **THEN** 已配置的本地 SDK 能通过宿主内容工具修改和保存基础 DOCX、CSV、XLSX、PPTX，再次打开能读取保存内容；缺少 SDK 资源时报告不可用，不尝试联网安装；此能力不声明远程模型或未经验证的页面资源离线可用

### Requirement: 共享模型与统一保存
用户和 Agent SHALL 修改同一个就绪模型，原生创建、打开、保存、关闭及导出由宿主控制。Agent MUST NOT 直接调用原生 save_file 或传入其他保存路径；页面保存、快捷键、自动保存和最终交付 MUST 经过统一保存服务。

#### Scenario: 绕过保存路径
- **WHEN** Agent 直接调用原生 save_file 并指定其他 file_path
- **THEN** 调用被拒绝，当前文件及产物身份不改变

#### Scenario: 页面已显示但模型尚未就绪
- **WHEN** 编辑页面已加载，原生模型的内容查询尚未成功
- **THEN** 文档保持 opening，不允许 Agent 内容修改或确认最终保存

#### Scenario: 工具运行期间切换文件标签
- **WHEN** Agent 对文档 A 发起修改，完成前用户切换到文档 B
- **THEN** 完成结果仍按调用时的实际模型 ID 登记 A，最终交付按真实工具父消息绑定轮次

#### Scenario: 保存失败后关闭
- **WHEN** 用户选择保存并关闭但保存失败
- **THEN** 保留当前模型与未保存状态，不销毁页面，不把磁盘旧版确认为成功交付

#### Scenario: 引擎队列仍在执行或交付尚未结束
- **WHEN** 当前聊天没有宿主 run，但实际引擎任务仍在执行，或当前文档仍在等待交付确认
- **THEN** 关闭、外部接管、导出准备及故障恢复均被拒绝，保留模型；活动查询失败也不能视为空闲

#### Scenario: 宿主重命名、覆盖或删除存活模型的路径
- **WHEN** 文件接口修改已打开 Office 文件、其父目录或重命名目标
- **THEN** 磁盘操作被拒绝并提示先保存关闭，不改动文件、模型、标签及产物身份；关闭后允许重命名，再次打开使用新路径

### Requirement: 外部应用交接
默认应用打开 SHALL 先保存、释放内置模型并停止内部写入，再启动系统应用。用户主动重新载入成功后才能恢复内部编辑。

#### Scenario: 外部修改返回
- **WHEN** 用户在外部应用保存关闭后选择重新载入
- **THEN** 导入最新磁盘内容并获取新 ID，不用过期内存模型覆盖文件

### Requirement: 格式保真
Excel 编辑 MUST 保留多表及已验收公式对象，PPT MUST 保留未修改的已验收对象，三种格式 SHALL 通过目标 Office 或 WPS 保存往返验证。

#### Scenario: Excel 无引擎回退
- **WHEN** XLSX 的原生编辑不可用
- **THEN** 不使用重建单张 Sheet1 的可写回退，提供文件信息及外部打开

#### Scenario: 已确认导入损失的 Excel 透视表
- **WHEN** 打开的 XLSX 内容类型清单包含数据透视表或透视缓存
- **THEN** 在建立原生文档或页面前要求只读，清除该聊天之前的活动编辑目标；侧栏和独立文件浏览器均直接读取原件预览多张表和缓存结果，禁用保存与 AI 编辑，保留默认应用打开和导出原件副本，磁盘文件不变；不通过拼回旧部件掩盖模型损坏

#### Scenario: 保存或恢复前原件已经变为不兼容工作簿
- **WHEN** 已打开文件在保存或故障恢复前，原路径 XLSX 检查发现透视表或缓存
- **THEN** 拒绝保存或重新导入，保留原文件和当前未保存模型，不释放旧模型后再尝试导入；检查解析失败不能当作兼容通过

### Requirement: CSV 原生编辑与原格式保存
CSV SHALL 与 Word 共用本地 Office SDK、编辑容器及保存生命周期，按 sheet 模型进行就绪查询和内容修改。系统 MUST 将 CSV 保持为 UTF-8 文本格式，MUST NOT 将 XLSX 二进制内容保存到 CSV 路径。

#### Scenario: CSV 修改及重新打开
- **WHEN** 用户在原生表格页面或 Agent 通过 sheet 内容工具修改 CSV 并保存
- **THEN** 宿主保存到原 CSV 路径，dirty 状态清除，重新导入后仍为相同单表数据；Word 内容工具不能作用于 CSV 模型

#### Scenario: CSV 增加额外工作表
- **WHEN** 原生 CSV 模型包含多个工作表且用户请求保存
- **THEN** 保存被拒绝并说明 CSV 只支持单个工作表，保留模型与未保存内容，不静默丢弃额外工作表

### Requirement: 引擎故障恢复
引擎退出后系统 MUST 清除失效原生模型身份及页面地址，禁止旧查询或保存结果恢复 ready 或确认交付。恢复 SHALL 仅载入原路径最后保存版本，经过原生确认并保留文档、聊天和文件标签身份；恢复完成后通知两种宿主。

#### Scenario: 保存响应晚于引擎退出
- **WHEN** 保存请求尚未完成时引擎退出，旧请求随后成功或失败
- **THEN** 文档保持 error，失效模型身份不恢复，该保存不被确认交付

#### Scenario: 原生页面崩溃或加载失败
- **WHEN** 原生进程仍存活，但文档编辑页面崩溃或无法加载
- **THEN** 仅该文档进入 error，停止自动保存及 Agent 内容修改，清除模型身份及页面地址并同步两处恢复入口；保留残留模型直到用户确认恢复，旧页面事件及保存响应不能覆盖新状态，恢复前释放旧协议处理器

#### Scenario: 用户取消或运行中恢复
- **WHEN** 用户取消恢复确认，或当前聊天仍有执行任务
- **THEN** 保留原状态，不销毁页面、不丢弃残留修改、不重新导入

#### Scenario: 从已保存版本恢复
- **WHEN** 用户确认丢弃未保存修改及撤销记录，原路径文件存在且聊天空闲
- **THEN** 等待旧保存结束后从原路径建立模型，保持 documentId 及标签，双宿主更新状态，并经格式对应查询确认 ready

### Requirement: 原生 Excel 与 PPT 编辑入口
本机 XLSX、PPTX SHALL 由与 Word 相同的 Office 宿主加载对应原生页面，普通文件 tab、独立窗口及历史产物 tab MUST 使用相同格式定义。XLSX MUST 保留完整工作簿，PPTX MUST 使用实际页面和对象身份；保存、关闭、外部接管及最终交付 SHALL 共用现有服务。

#### Scenario: XLSX 多表保存
- **WHEN** 用户或 Agent 修改两张工作表中的数据并保存 XLSX
- **THEN** 原生引擎保存整个工作簿，重新打开后两张表及跨表公式仍在，不应用 CSV 单工作表限制，也不使用二维字符串重建 Sheet1

#### Scenario: XLSX 标准公式导出
- **WHEN** 原生 SDK 导出的工作表公式节点包含界面输入用的前导等号
- **THEN** 统一保存出口在成功确认前按 ZIP/XML 格式移除该前导等号，保留共享及数组公式属性、缓存值和其他工作簿部件；标准公式不重复改写，解析或替换失败不得确认保存交付

#### Scenario: PPT 导入尚未完成
- **WHEN** slide_get_info 返回成功但 is_open 为 false
- **THEN** 文档保持 opening，禁止内容修改及最终保存，模型 is_open 为 true 后才进入 ready

#### Scenario: PPT 修改与格式隔离
- **WHEN** Agent 修改 PPTX 页面上的文本对象并保存
- **THEN** 操作限定当前聊天实际 slide 模型，未修改页保持原内容，Word 或表格内容工具不能作用于该模型

### Requirement: Office 内容能力按需发现
系统 SHALL 使用现有语义查询按当前聊天文档格式返回内容工具名称或单个原始参数定义，并通过宿主执行内容工具。系统 SHALL NOT 向模型注册完整原生 Office MCP 目录。内容调用 MUST 使用真实调用聊天和模型身份，修改成功后登记本轮交付。

#### Scenario: 查询和编辑当前表格
- **WHEN** Agent 查询 sheet_delete_dimension 的参数并请求删除当前 CSV 首行
- **THEN** 仅返回该工具定义；宿主绑定实际模型，拒绝其他聊天、错误格式和生命周期工具；修改登记到调用消息所属轮次，统一保存写回原路径

#### Scenario: 同一聊天切换文档格式后继续编辑
- **WHEN** 用户依次打开 DOCX、XLSX、PPTX 并要求修改当前文件
- **THEN** 每轮使用当前格式的就绪模型及工具参数，Word 替换保留非目标正文，Excel 修改保留非目标单元格及跨表公式，PPT 修改保留非目标页面与页数；各轮只交付实际修改并保存的文件

### Requirement: 保存等待所属页面输入提交
DOCX、CSV、XLSX、PPTX 统一保存 SHALL 等待所属存活页面的输入提交和原生确认，不以模型 dirty=false 代替页面提交就绪。Word SHALL 等待输入合并及提交确认；CSV、XLSX SHALL 等待输入法组合结束并提交当前单元格，原生确认成功后才退出编辑，避免重复提交。PPT SHALL 使用自身文字输入及提交队列契约，等待组合结束、提交文字缓冲并等待原生确认；SDK 队列吞掉的 HTTP 提交失败 MUST 独立保留，当前页面后续成功不能掩盖已丢失的修改。页面确认 MUST 绑定 workspaceId、documentId、pageId；状态未知、原生提交失败、超时或页面失效 MUST 拒绝继续写盘并保留编辑内容。纯引擎宿主没有页面时无需桌面确认。

#### Scenario: PPT 中文上屏后立即保存
- **WHEN** 用户在侧栏或独立窗口的 PPT 文字框提交中文后，不回车立即保存
- **THEN** 宿主先提交该文字框缓冲并等待原生确认，原文件包含最新中文，其他页面保留；存活页面迁移后遵循相同规则

#### Scenario: PPT 队列吞掉原生提交失败
- **WHEN** PPT 原生提交返回非成功结果、无效响应或传输失败，但 SDK 内部队列正常结束
- **THEN** 宿主仍拒绝写盘且不报告保存成功，当前页面后续提交成功不清除该错误，恢复后的新页面重新建立状态

#### Scenario: 中文上屏后立即保存
- **WHEN** 用户在侧栏或独立 Word 窗口提交中文组合输入后立即保存
- **THEN** 等待该页面输入提交原生模型后写入原文件，新上屏文字不得留到下一次自动保存

#### Scenario: 表格单元格未回车直接保存
- **WHEN** 用户在侧栏或独立窗口的 CSV、XLSX 单元格中完成中文上屏，未按回车便立即保存
- **THEN** 等待该单元格提交原生模型后写入原文件，新文字落盘，非目标单元格与其他工作表保留；提交失败或超时不退出当前编辑，也不继续写盘

#### Scenario: 组合期间文档快捷键
- **WHEN** 原生编辑区的输入法仍在组合文字，用户按保存、打开或关闭快捷键
- **THEN** 阻止对应文档快捷键，不执行宿主动作，也不让 SDK 自身保存组合中的拼音或提前退出编辑

#### Scenario: 页面提交等待期间失效
- **WHEN** 等待原生提交确认时页面崩溃或文档恢复为新页面
- **THEN** 旧页面不能确认新模型保存，保持失败结果，不写入旧版内容

### Requirement: 按平台开放存活页面迁移
系统 SHALL 将首次创建编辑页面与跨窗口迁移分开控制。首次打开使用实际平台 SDK 资源检查；已有存活页面的跨窗口迁移 MUST 仅在已验收的平台开放，当前为 macOS ARM64。未经验证的平台 MUST NOT 关闭重开模型来冒充保持状态迁移。

#### Scenario: 未验收平台首次打开文件
- **WHEN** 当前平台具备匹配的本地 SDK 且文档尚无存活页面
- **THEN** 可直接在侧栏或独立文件浏览器首次创建页面，不要求迁移能力

#### Scenario: 未验收平台请求迁移已有编辑页面
- **WHEN** Windows、macOS Intel 或其他未验收平台从任一窗口请求在另一窗口接续已有 Office 页面
- **THEN** 在等待任务、保存或重挂之前拒绝迁移，提示先保存并关闭文档再在目标窗口打开；保留原页面、模型、dirty 内容及宿主归属，清理新建的空文件窗口；直接分配入口遵循相同规则

### Requirement: SDK 随源码与安装包自包含交付
SDK 原生资源 SHALL 使用 Git LFS 纳入版本管理，wrapper 和清单 SHALL 使用普通 Git；仅运行日志和临时文件可忽略。桌面构建 SHALL 检出 LFS 实体，安装包 SHALL 在 ASAR 外包含唯一目标平台的完整 SDK、wrapper 及版本哈希清单，不得依赖外部 App 或运行时下载补全。

#### Scenario: 当前 Office 资源导入
- **WHEN** 导入包含 wrapper、平台目录及版本清单的当前 Office 资源
- **THEN** 复用打包资源校验并确认包名为 office-docs-ai-engine，服务入口为 office-docs-service.js 且导出 OfficeDocsService；配套版本、文件及 SHA-256 不匹配时拒绝复制，不提供其他包格式转换或旧名称别名，原生二进制与许可原文保持不变；源与目标按真实目录身份比较，同源别名只校验，真实路径互相嵌套则拒绝复制，尚不存在的目标先解析其最近的真实父目录

#### Scenario: 多平台资源共存并分别交付
- **WHEN** 源资源包含 darwin-arm64、darwin-x64、win32-x64 的配套引擎，构建选择其中一个目标平台
- **THEN** 使用该平台独立清单校验和复制完整目录，安装资源只包含其原生引擎与匹配 wrapper；不复制其他平台、不把 ARM64 文件重命名成 x64；取得资源不代表目标平台桌面及跨窗口迁移已经验收

#### Scenario: 内置 Server 的生产依赖随桌面交付
- **WHEN** 构建桌面安装包并暂存内置 Server
- **THEN** 桌面打包入口包含 Server 配套的生产依赖，XML/ZIP 处理库不因只声明在源码 Server 中而漏包；使用 Electron 内置 Node 验证暂存 embedded.js 可导入，依赖缺失时构建失败，不以源码目录能够解析依赖作为通过依据

#### Scenario: 供应平台资源缺失或未检出 LFS 实体
- **WHEN** darwin-arm64、darwin-x64 或 win32-x64 安装包的目标平台未提供完整 SDK，或原生文件只是 LFS 指针
- **THEN** 打包明确失败，不复制其他架构代替，不联网下载或从外部 App 找资源

#### Scenario: 未供应 Office SDK 的桌面平台
- **WHEN** 构建 Windows ARM64 等未列入 Office SDK 供应范围的桌面目标
- **THEN** 保留桌面构建及普通文件功能，不要求不存在的 Office SDK，不复制其他架构内核；运行时报告原生 Office 编辑不可用

#### Scenario: 安装后从桌面启动 Office
- **WHEN** JuggleWork 安装后打开支持的本地文档
- **THEN** 桌面显式传入 process.resourcesPath/office-engine，Server 从该目录加载；源码工作目录及环境变量不替换桌面资源路径；原生进程的工作目录、日志和临时文件使用用户数据区，不修改安装资源

#### Scenario: macOS 签名改变 SDK 原生字节
- **WHEN** electron-builder 使用实际选定的身份与钥匙串签署应用
- **THEN** 先用该身份签 SDK 并更新安装包清单哈希，再沿用默认签名器封存主应用；不再次改写 SDK，也不修改源码 SDK 快照；SDK 签名失败不能继续封存应用

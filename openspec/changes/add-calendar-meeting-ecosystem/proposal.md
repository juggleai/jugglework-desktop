# Proposal

## Why

原生日历和团队协作稳定后，办公场景还需要视频会议、会议室、对外预约和外部日历互操作。它们具有不同的供应商、资源排他、公开访问和同步一致性风险，应作为独立后续阶段接入，而不是污染核心日程模型。

## What Changes

- 在前三阶段稳定后，新增可插拔的视频会议关联能力：显式创建、更新、取消并把连接信息附加到日程，而不是把会议供应商字段写死在日程主模型中。
- 新增会议室等组织资源目录、可用性查询、排他预订、并发冲突处理和授权管理。
- 新增对外预约类型、公开预约页面、可预约时段、时区、缓冲时间、取消/改期和防重复预订。
- 新增外部日历连接的映射、初始导入、增量同步、来源权威、冲突/错误状态和断连行为；按供应商能力分阶段启用只读或受控写回。
- 为会议、资源、预约和外部同步提供 Desktop 管理入口、状态反馈、审计与故障恢复。
- 不在规格中预先绑定具体会议或外部日历供应商；实施前必须为选定连接器补充能力、授权和配额验证。

## Capabilities

### New Capabilities

- `calendar-conferencing`: 供应商无关的视频会议创建、关联、生命周期、权限与失败恢复。
- `calendar-resource-booking`: 会议室等排他资源的目录、可用性、预订、冲突与管理。
- `calendar-appointment-scheduling`: 对外预约类型、公开可用时段、预约、取消、改期与滥用防护。
- `external-calendar-interoperability`: 外部日历映射、增量同步、来源权威、冲突处理和连接状态。

### Modified Capabilities

无。

## Impact

- 前置条件：核心日历、办公排期和团队协作阶段已完成；每项生态子能力可在本阶段内按 feature flag 独立灰度。
- `jugglework-server`：新增会议关联、资源预订、公开预约、外部映射/同步游标、投递记录、webhook 与审计边界。
- `jugglework-desktop`：新增会议、会议室、预约和外部日历设置与状态界面。
- JuggleWork Connect 或组织发布的连接能力可作为供应商接入路径，但连接器操作不等于 JuggleWork 原生日历存储。
- 涉及公开端点、第三方 OAuth、webhook、配额、隐私和跨系统删除传播，必须在实施前进行单独安全及可靠性评审。

Claude Agent uses a credential broker and an isolated local profile. Its
credential path is separate from both a standalone Claude installation and an
Anthropic model configured for the default JuggleWork/OpenCode runtime.

<Warning>
Adding Anthropic under the normal model-provider settings does not by itself
provision the dedicated Claude Agent credential store. If your build does not
offer an administrator-approved Claude Agent credential setup, the runtime
correctly remains unavailable with `credential_missing`.
</Warning>

## Credential handling

The standard Desktop integration supports an Anthropic BYOK credential supplied
through JuggleWork's dedicated Claude secret provider. The encrypted record is
stored beneath the active Electron profile as
`claude-anthropic-byok.json`; plaintext is encrypted and decrypted with
Electron `safeStorage`.

- macOS and Windows use the platform secure-storage backend selected by
  Electron.
- Linux refuses `basic_text` and unknown storage backends instead of storing a
  recoverable plaintext credential.
- The Renderer receives readiness categories, not credential values.
- The Server leases credentials to the worker only for the worker generation.
- Worker and Claude subprocess environments are built from allowlists rather
  than inheriting the full parent environment.
- Credential values are excluded from canonical session state, workspace
  files, worker responses, and routine diagnostics. Known secret formats and
  leased values are scrubbed from captured startup errors.

Approved source/library hosts can supply brokers for an HTTPS gateway, Amazon
Bedrock, Google Vertex AI, or Microsoft Foundry. Those brokers must be selected
and constrained by host policy; they are not enabled merely by setting provider
environment variables. See
[Administer and package Claude Agent](/cloud/share-with-your-team/claude-agent-administration).

Never put a provider key in a workspace file, prompt, migration preview,
`server.json`, diagnostics attachment, or support ticket. Do not print a secret
record or dump the worker environment while troubleshooting. If exposure is
suspected, revoke the credential at its provider and replace the stored value.

## What data can leave the device

When you run Claude Agent, the configured Anthropic-compatible provider can
receive the prompt and the context required for that run. Tool execution can
also send selected file content, tool arguments, and tool results to the model.
An enabled external MCP server receives the arguments sent to its approved
tools according to that server's own privacy terms.

JuggleWork does not implicitly load a user's standalone `~/.claude` settings or
project `.mcp.json`. Runtime MCP configuration is generated from JuggleWork's
approved configuration. Workspace authorization, sensitive-path checks,
symlink resolution, command/network policy, and tool-specific validation remain
in force even when the runtime would otherwise approve a tool.

Cross-runtime continuation sends only the reviewed migration context to the new
session. The source remains unchanged. See
[Use Claude Agent sessions](/start-here/do-work-with-it/claude-agent-runtime)
for transfer limits and omissions.

## Local storage locations

`<profile-data>` below is Electron's active `userData` directory. Production
defaults are:

| Platform | `<profile-data>` |
| --- | --- |
| macOS | `~/Library/Application Support/com.juggleai.jugglework` |
| Linux | `~/.config/com.juggleai.jugglework` |
| Windows | `%APPDATA%\com.juggleai.jugglework` |

`JUGGLEWORK_ELECTRON_USERDATA` can replace that directory for a separately
launched Desktop profile.

| Data | Current location and contents |
| --- | --- |
| Claude configuration and backend transcripts | `<profile-data>/claude-agent/config`; SDK JSONL transcripts are under `config/projects`. This is separate from `~/.claude`. |
| Encrypted provider records | `<profile-data>/claude-anthropic-byok.json` for Anthropic BYOK. Other approved broker secrets use name-suffixed files beside it. Files contain encrypted metadata, not plaintext. |
| Canonical sessions and projections | `runtime.sqlite` beside the active `server.json`, or the absolute `JUGGLEWORK_RUNTIME_DB` override. Desktop defaults to `~/.config/jugglework/runtime.sqlite` on macOS/Linux and `%APPDATA%\jugglework\runtime.sqlite` on Windows. |
| Workspace files | The workspace directories you authorized. They are not copied into the Claude profile merely because a session can read them. |

Do not assume these directories are safe to publish. Backend transcripts,
canonical messages, tool payloads, titles, local paths, and encrypted credential
records can all be sensitive.

## Current retention behavior

| Record | Implemented retention |
| --- | --- |
| Claude SDK JSONL transcripts | Files older than 30 days by modification time are removed when the Claude worker starts. The implementation accepts a host-provided value from 1 through 3,650 days, but Desktop currently uses the 30-day default. |
| Canonical events | The newest 10,000 events per session are retained. Event receipts retain up to 20,000 identifiers per session so duplicate backend events can still be recognized. |
| Canonical session/message/part/usage projection | Retained in `runtime.sqlite`; there is currently no time-based purge or standalone per-session deletion control on the canonical API. Event pruning does not delete the snapshot or messages. |
| Redacted tool-policy audit | 90 days, capped at 100,000 records per workspace. Expired records are purged when the audit repository opens; the per-workspace cap is enforced as records are added. |
| Support diagnostics | Generated on demand. The bundle contains counters and categorized runtime state rather than prompts or transcript bodies, but review it before sharing. |

Backups and filesystem snapshots can retain deleted records beyond these live
application limits. Self-hosted operators must align backup, log, and media
retention separately.

## Delete local data

Desktop's **Settings -> Developer -> Nuke & fresh start** is the implemented
full local reset. The confirmation preview lists exact paths before deletion.
It removes the Desktop profile, Server runtime database and config, local
tokens, environment store, OpenCode state, caches, and legacy orchestrator
state. Workspace folders and each workspace's `.opencode` directory are not
deleted. The bootstrap/organization-server file is preserved by default unless
you turn that option off.

This is a broad reset, not a per-Claude-session erase. Back up any data you need,
stop active runs, inspect the deletion preview, and do not manually delete a
database while JuggleWork is running. Deleting local state does not revoke a
provider credential remotely; revoke it at the provider when required.
